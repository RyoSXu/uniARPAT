# 研究、执行与交接流程

当前问题见[状态](status.md)，固定边界见[决策](decisions.md)，接手检查见[交接](handoff.md)。

## 从问题到结果

1. **理解与核查。** 阅读当前状态、相关证据和代码调用链，区分事实、推断与假设；不从最近结束的候选自动续跑。
2. **提出有限方案。** 可跨 encoder、decoder/head、目标和数据思考，不受历史候选白名单限制。说明支持与反证、主要成本和可区分的解释，由用户决定方向。
3. **准备可执行协议。** 明确对照/候选、数据与 split、任务和 blind/oracle、loss/选点、预算、采用标准及各种结果的行动。按问题选择单因素或完整架构对照，不预设固定 pilot。
4. **实施与短检。** 搜索复用既有入口，检查工作区；完成获准的实现、相关测试、真实批成本预检和指纹绑定。短检不代表完整训练的显存/速度保证。
5. **核验与判读。** 用 train/valid 开发，核对完整 cohort、标签、有效配置、history 选点和 checkpoint 契约；从原谱独立复算关键结果。先报告事实和边界，再由用户决定采用。

## 长时间实验交给执行 agent

准备 agent 不直接启动整轮/多轮训练或接管持续监控。代码、测试和必要短检完成后，在回复中提供精简且自包含的提示词，由用户交给新 agent，不另存提示词文件。
规则及执行 agent 的授权例外见 [AGENTS.md](../AGENTS.md#长时间实验与监控)。

提示词应足以让执行 agent 独立完成：

- 明确它负责本次实验执行，给出获准问题、对照、固定条件和成功/停止判据。
- 指向本轮设计、准备与预检报告、冻结协议、准确原始命令、唯一标签和输出目录；执行前核对输入/源码指纹与资源。
- 训练与排队用脱离会话的脚本运行和监控；agent 按事件唤醒并约 30 分钟保底检查，每完成一次训练汇报一次，持续跟进到 valid 导出、分析、独立核验和文档更新。同一时间只有一个监控者。细则见 [AGENTS.md](../AGENTS.md#长时间实验与监控)；监控不能保证平台不会杀进程。
- OOM、NaN/Inf、契约不符或异常中断时停止并汇报；不自行调参、改预算、重训对照、追加候选或用 test。
- 恢复前验证 checkpoint/history、优化器、RNG 与原契约；best/latest 各守用途，不覆盖旧证据，不自动采用或提交推送。

## 文档维护

- `status.md` 只写当前工作点、阶段结论和未解决问题；`decisions.md` 写固定契约，`data.md` 写数据边界，`handoff.md` 写恢复步骤与必要产物。`index.md` 只导航，避免重复抄录结果。
- 每项实验在 `design/` 记录事先协议、在 `logs/` 记录执行与核验；完成后补结果链接，不把旧待办当新指令。历史结果不因新选点规则追溯重写。
- 新设计/日志用创建日期命名，不因更新改编号。模板见 [design/template.md](design/template.md)、[logs/template.md](logs/template.md)；历史改名依据见[迁移登记](../archive/metadata/repository-migration-2026-10-04.json)。
- 文档改动检查链接、过时表述和差异；代码改动运行相关检查。只报告实际执行的验证，保留用户已有改动。
