## 2026-10-04：实际存储格式与历史版本区别

**已核实事实：**当前 Q1 的 `positions_train.npy` 将两个晶格行和原子分数坐标放在同一个
数组中，reshape 后为每结构 `[82,3]`：

| 位置 | 当前含义 | 单位 |
|---|---|---|
| 第 0 行 | `(a,b,1/c)` | 前两项 Å，第三项 Å⁻¹ |
| 第 1 行 | `(α,β,γ)` | 度 |
| 第 2 行起 | 原子分数坐标，含填充槽 | 无量纲 |

本次只读查看当前 train 缓存的第一条记录，晶格行为：

```text
[5.4186606, 5.4186606, 0.18454745]
[109.47122, 109.47122, 109.47122]
```

第三项取倒数后 `c≈5.41866 Å`。这段样本读取仅用于核查格式，没有加载谱标签或 test。
[`Dos_Dataset.get_positions`](../../utils/dataset.py) 直接加载缓存并转成浮点张量，
`__getitem__` 将其 reshape；上述晶格字段没有在这两处另做归一化转换。
[`build_cell_from_lattice`](../../utils/relative_features.py) 直接读取 `a/b`、从 `1/c` 恢复 `c`，
再将角度从度转换成弧度。

用户记忆中的格式也有历史代码依据：本地参照文件
`/root/home/newstudy/getdata/ref/MP_dos.ipynb` 与 `MP_pdos.ipynb` 使用
`(1/a,1/b,1/c)` 和 `(α/180,β/180,γ/180)`；
`mp_edos_data.ipynb` 则使用 `(a,b,1/c)` 和度数。
这些是仓库外的本地历史参照，不构成当前缓存生成过程的完整追溯。
**两个格式具体何时、如何切换及当初为何只对 c 取倒数，尚未定位明确依据。**
不得根据文件名、数值大小或旧记忆自动推断任意新数据的格式。

### 关于直接存储 c 的判断

对于物理几何，直接存储 `(a,b,c)`、统一单位 Å 更清楚，也省去取倒数与恢复操作。
两种存法字段数量、存储空间相同；倒数转换成本很小，目前没有性能测试支持明显速度收益。
取倒数可能压缩长轴的数值范围，但这只是一般性质，不是已确认的历史设计动机；
当前几何路径会先恢复 c，不能据此认定倒数格式给当前消息网络带来收益。

推荐今后物理接口直接使用真实长度或晶胞矩阵。当前 Q1 格式仍保持原样；转换磁盘字段
需要明确版本并同时处理读取、校验、CIF 推理入口和历史模型兼容性，不能只改一个数组字段。

## 2026-10-04：晶格信息已经怎样被利用

晶格长度和角度用于重建以基矢为行的晶胞矩阵 `A`。分数坐标只有与晶格共同解释，才能得到
真实位置和周期位移：

\[
x_i=f_iA,\qquad r_{i\to(j,T)}=(f_j-f_i+T)A,\qquad d=\|r\|.
\]

位移计算依据为 [`periodic_edge_vectors`](../../utils/periodic_geometry.py)。
晶格因此已经影响 6.0 Å 内的周期镜像集合、距离、位移方向、邻边夹角和记录计数，
这些量通过 A/B+ 局部消息参与原子状态更新。把六个参数拆出位置数组，不会取消这种使用。

当前独立局部模块接收物理记录，并未额外把原始六个晶格参数拼入普通神经网络输入。
现有 [`Transformer.forward`](../../model/transformer.py) 另有可选 `use_macro_lattice` 分支，
[`macro_lattice_features`](../../archive/code/utils/macro_lattice.py) 生成标准化的
`log(V/N)` 和 `log(total_mass/V)`，再经可学习投影作为原子状态的共同残差。
此分支仅在对应开关启用时使用；其存在不表示当前独立 A/B+ 检查或所有训练配置已经使用它。

是否为新 Encoder 额外提供每原子体积、密度等晶体级特征，是待决定项。
几何计算使用晶格，不等于神经网络已获得或有效利用所有全局结构信息；额外入口的收益需对照。
原始六参数在等价换基下可能变化，不宜未经契约设计就直接作为全局不变特征。

## 2026-10-04：推荐拆分后的结构接口（未实施）

推荐将晶格与原子字段分开表达，仍归属于同一个晶体结构对象，按同一批次编号关联。
字段拆分不要求分成多个磁盘文件，也不要求立即迁移现有缓存。

| 推荐字段名 | 单个结构的形状 | 含义与约定 |
|---|---|---|
| `cell` | `[3,3]` | 真实晶格基矢为行，单位 Å；不与位置数值一起隐式归一化 |
| `frac_coords` | `[N,3]` | 原子分数坐标，无量纲；顺序与原子编号一致 |
| `atomic_numbers` | `[N]` | 原子序号，供 ZP 使用 |
| `padding_mask` | 批次填充后 `[B,L]` | `True` 为填充；晶格不占原子槽 |

批次形式对应 `cell[B,3,3]`、`frac_coords[B,L,3]` 和 `atomic_numbers[B,L]`。
六个长度/角度参数可按需要保留为明确单位的来源元数据，或由 cell 派生供展示；若保留两份
描述，应指定 cell 为几何计算依据并核对一致性，避免两份独立更新而失配。
这里的字段名和形状是接口建议，不是已经新增的类、函数或当前生产数据契约。

推荐职责与数据流：

```text
现有缓存或 CIF → 明确格式的结构适配层 → cell / frac_coords / atomic_numbers / mask
atomic_numbers → ZP → 原子标量 h
cell + frac_coords + mask + 显式 radius → 周期物理记录
h + 周期物理记录 + mask → A/B+ → 后续 Encoder 与读出
```

适配层负责解释存储格式、单位和原子槽；几何层负责物理记录；局部模块负责派生几何特征与
状态更新。ZP 不读取晶格或坐标，下游不依赖 A/B+ 私有球谐通道。
现有 `build_periodic_records(pos,padding_mask,radius)` 本轮不变，新入口签名尚未确定。

### 选择 cell 而不是六参数作为几何入口的理由

- 距离与镜像位移本就需要矩阵，显式 cell 避免在每个使用位置重新解释混合单位的六字段。
- 整体旋转/反射可直接表达为 `cell→cell·Q`，分数坐标不变，物理位移相应为 `r→rQ`。
  整体平移需实际改变所有原子位置或相应分数坐标，不能把未改变的输入当成平移测试。
- 六参数只描述晶胞的长度与夹角，不保留任意外部朝向。从旧缓存重建的 cell 仍是规范框架，
  不会自动恢复一个原本没有存储的外部朝向；任意物理框架需显式提供或变换。
- 晶格有效性应按物理长度、有限性与非退化矩阵检查。反射允许改变行列式符号，不能仅因
  `det(cell)<0` 拒绝合法物理框架；体积使用绝对行列式。

显式矩阵接口本身不保证模型不变。任意矩阵分量直接进入普通 MLP 可能破坏 E(3)；
cell 应通过保持对称性的几何运算使用。等价换基须同时变换 cell 与分数坐标，另做记录与输出
一致性检查，不能将更换矩阵单独视作同一结构。超胞按其既定契约另验收。

## 2026-10-04：建议实施顺序与验收边界

以下是后续建议，需另行确认实施范围：

1. 先明确结构字段的单位、行向量约定、原子排序、掩码、device/dtype 与格式版本。
2. 保留旧缓存与历史入口，在读取边界转换当前 `(a,b,1/c)` 和度数，提供显式 cell/坐标字段；
   用同一结构对照新旧几何，确认没有单位、方向、镜像或原子槽变化。
3. 在明确兼容范围后增加独立几何入口，保持已有六字段邻居记录与 A/B+ 外部消息接口；
   重新验收 CPU/GPU、平移/旋转/反射、重排与等价晶胞表达。旧接口适配策略需另定。
4. 只有在确有需要时，再决定磁盘格式迁移或是否保留六参数元数据。显式登记格式版本、
   来源/哈希与 checkpoint 兼容边界，不覆盖历史证据，不从输入格式变化推断历史模型一定兼容。
5. 与完整 Encoder 方案衔接，分别验收最终 eDOS/phDOS 输出不变性、资源成本和训练收益。

## 2026-10-04：已实施的数据契约

### 来源和修复

以冻结 Q1 的 ID、顺序、划分、E0/P0 谱数组和覆盖标签为基底。A4 的生产结构来源为 MP，
采用 `SpacegroupAnalyzer(...,symprec=0.1).get_primitive_standard_structure()`；
依据为 [A4 收官日志](../../archive/docs/logs/log-2026-09-12-A4收官.md)、
[Topup 日志](../../archive/docs/logs/log-2026-09-12-Topup收官.md)及 Git 中原 `a4_process.py`。
没有混入 JARVIS/PhononDB 晶体结构，也没有从谱标签重新选择晶胞。

Q1 的 23,306 条记录中，55 条仍只有前 80 个原子；原处理表 `nsites_prim` 保存了完整数量。
这些记录均可从本地 `mp_increment_raw.jsonl` 恢复。新转换工具检查原胞数量、前 80 个元素、
晶格参数以及模整数平移后的坐标一致性；保留已有坐标前缀的原始 FP32 表达，再追加完整尾部。
全部存储结构合计 275,049 个原子，最大 192，不再设置原子数上限。

同时发现 54 条大结构的 `N_val` 回退值等于前 80 个原子的元素价电子数之和。
新版本按完整组成修复这些回退值；其余冻结材料自身电子谱审计值保留，仅统一存为 FP32。
修复后的电子谱完整率沿用既定公式 `trunc=C_full/N_val`，其中历史表的完整率乘
`N_val_old/N_val_new` 得到新比值。两条 train 记录低于原有 0.5 隔离阈值：

| 材料 | 完整原子数 | 旧 N_val | 新 N_val | 修正后完整率 |
|---|---:|---:|---:|---:|
| mp-aaabidtd | 180 | 360 | 960 | 0.207431 |
| mp-aaabilxy | 192 | 304 | 896 | 0.172566 |

完整原始 Q1 成员仍存盘供追溯；新训练视图隔离以上两条，因此实际训练 18,704，valid 2,313、
test 2,287。没有修改任何谱值、覆盖标签或原始划分，没有用 test 指标选择质量阈值或模型。
这个修复版本不能当成历史 Q1 训练结果的逐步复现。

### 存储

新目录为 `data/crystal_q1_v1/`，格式名为 `crystal-q1-v1`。每个 split 单独保存以下 `.npy`：

| 字段 | 数组形状 | 磁盘 dtype | 单位/用途 |
|---|---|---|---|
| `cell` | `[M,3,3]` | float32 | 晶格基矢为行，Å，唯一计算几何真值 |
| `frac_coords` | `[S,3]` | float32 | 同原胞基底下的完整分数坐标，无量纲 |
| `atomic_numbers` | `[S]` | uint8 | 元素序号，无填充或晶格哨兵 |
| `atom_offsets` | `[M+1]` | int64 | 结构 i 的原子区间为 `[offset[i],offset[i+1])` |
| `n_atoms` | `[M]` | int32 | 完整原子数，与 offset 差一致 |
| `{split}_index` | `[M]` | Unicode | 冻结 Q1 材料 ID 与行序 |
| `edos_tgtdos` | `[M,128]` | float32 | 原 Q1 E0 谱值 |
| `phdos_tgtdos` | `[M,64]` | float32 | 原 Q1 P0 谱值 |
| `edos_mask/phdos_mask` | `[M,128]/[M,64]` | bool | True 表示有覆盖 |
| `nvalence` | `[M]` | float32 | 与完整组成对应的 H1 尺度元数据 |

`M` 是 split 的原始 Q1 行数，`S` 是其完整原子数总和；文件名除 ID 外为 `{字段}_{split}.npy`。
磁盘没有原子填充槽，也没有 126/127 晶格哨兵。`manifest.json` 记录 dtype、shape、SHA-256、
来源、修复明细、质量隔离名单和规则。旧 `data/train4ARPAT/` 及历史 checkpoint 没有覆盖。

历史 Q1 六参数转换成矩阵时，使用现有 FP32 `build_cell_from_lattice` 一次，保持原规范框架
与数值口径；它不能恢复原缓存未保存的朝向或精度。运行时原生矩阵直接参与计算，不再转回
六参数。新 CIF 的默认策略与 A4 的 MP 标准原胞及缓存规范朝向一致，仅在导入边界作一次
明确的 FP32 参数转换；显式 `primitive=False` 保留供给的完整
矩阵及晶胞。分数坐标允许 1、整数平移和未折回值，只要求真实原子坐标有限。

### 调用链与精度

```text
migrate_crystal_q1 → 完整 FP32 packed arrays + manifest
PackedCrystalStore → Dos_Dataset（train 质量视图）→ crystal_collate
atomic_numbers[B,L] → ZP → 原有 Encoder/decoder/head
CrystalGeometry(cell[B,3,3],frac_coords[B,L,3]) → 原生矩阵几何
build_periodic_records → 既有六字段物理记录 → 独立 A/B+（架构尚未接入）
```

`padding_mask=atomic_numbers.eq(0)`，True 表示 batch 填充；它与 coverage mask 的含义不同。
原子序号在运行时转 `torch.long`；组批只填充到该 batch 的真实最大 N。`3N`、ZP 输入和
周期邻居均使用完整原子区间。公共几何函数接受 `CrystalGeometry`，同时保留旧 Tensor 适配
入口；矩阵允许负行列式，体积取绝对行列式。

新生产存储和训练使用 FP32；FP64 仅作为几何数值参考能力保留，不能恢复上游已量化的坐标。
严格截止仍为 `d<R`，在最终消费 dtype 中枚举；不要先用 FP64 选边再盲目转 FP32。
数据格式变化没有将旧 Encoder 的单镜像近似改成多镜像架构，也不证明完整模型满足 E(3)。

### 资源与兼容边界

按 `B*L²` 控制计算批次规模。默认预算为 `max(B*6400,max_N²)`，6400 是历史每样本
80² 原子对规模的资源参考，**不是原子上限**；192 原子的单结构也能通过自动预算。
同一个样本 batch 内按原顺序拆分计算，每个子批次的损失按 `B_sub/B_total` 加权，
累计梯度后只更新一次；不删除原子、不丢样本、不缩小等效 batch。显式预算不足以容纳一个
完整结构时，明确报错并要求增加预算，禁止裁原子。预算是张量规模估算，不是显存字节保证。

默认 CLI/config/template 指向新目录，原 Q1 只能显式作为历史输入指定。
新训练支持当前 FP32 SumNorm/H1 链路；AMP、batch 非加性辅助损失和旧训练 checkpoint
不能自动混用。恢复和初始化检查数据 manifest 指纹与归一化契约；历史权重参数形状相同
并不代表修复后输入/尺度语义相同。

`structure_to_crystal_inputs` 是新 CIF/Structure 转换入口，无 80 原子上限；
`structure_to_b7_inputs` 和 `infer_b7_cif.py` 保留历史 B7 冻结契约及原限制，供旧模型复核。
新格式没有获准的已训练 checkpoint，本轮不输出新模型的 CIF 预测。

验收包括存储字段与谱值一致性、完整原子进入模型和梯度、样本加权累积梯度一致性、
几何矩阵/反射、原子计数、checkpoint 版本隔离以及 V100 完整规模前向/反向。
CPU/GPU 局部数值通过不代表新的 DOS 收益或完整模型对称性已验收；没有启动正式训练。
