# 设计：冻结 G2 消息参数的固定16对互补拟合

## 授权、问题与相反结果

- 马尚酱批准“冻结G2，只训练其余encoder与读出”的互补对照，本轮新增一个训练臂。
- 同一16对材料、2000步下，冻结encoder末步8／16通过，全encoder更新第700步首次16／16，
  仅G2更新最多10／16、末步4／16。后者不能单独指认普通encoder的哪个模块，也有优化不稳定。
- 本轮以全encoder更新为对照，唯一改动是冻结全部6个G2消息模块的参数，检验其余encoder
  与原读出更新是否足以拟合。若通过，排除“拟合这批材料必须更新G2消息参数”；若未通过，
  此预算下仍保留协同适配与优化设置解释，不宣称G2不可替代或缺少某类信息。

## 数据、初值、参数范围

- 复用`output/g2_small_fit_q1/train_cache.pt`、同一16对selection和原G2 ep10／seed42
  检查点。验证选样、源文件和缓存哈希，不重新抽样，不接用任何已训练的小样本权重。
- 只使用缓存中的32个Q1 train材料；valid／test不加载或评估，phDOS不作为验收项。
- `non_g2`臂：冻结`encoder.g2_msgs.*`的W_v、W_g、W_o、alpha及H1；开放其余encoder
  的注意力、相对位置投影、前馈、归一化参数和原读出。atom_src输入及原元素嵌入固定。
- G2参数冻结，G2前向仍保留，梯度需穿过G2传到早期普通encoder层。G2输出会随其输入变化；
  不能将“无需更新G2参数”解释为“无需G2模块”或“几何Value消息没有作用”。
- encoder可更新参数预期14,383,104／17,734,662（81.10%），读出仍25,357,825个参数。
  边界按实际参数名及逐值比较核查，不只根据数量判断。

## 固定训练与拟合门槛

- FP32、eval模式、关闭dropout；同一完整16对batch重复2000步。读出与可训练encoder分别
  AdamW（lr5e-5、betas0.9／0.99、weight_decay0.01），各自梯度裁剪1.0。
- 目标沿用`mean((128*((p_a-p_b)-(q_a-q_b)))**2)`，无单谱锚定；更新集合改变会相应改变
  encoder的裁剪范数。比较是相同数据暴露及步数，不声称等算力。
- 每对残余MSE≤其零谱差MSE的1%，残余TV≤其目标TV的10%，要求16对同时通过；零目标差
  仍用MSE≤1e-12、TV≤1e-6。第0步及每100步评估，保存首次全部通过权重并继续满2000步。
- 报告首次通过、末步和全部检查点轨迹。未通过只能表示指定预算与优化条件下未获得见证；
  不修改阈值，不按最好均值替换末步，不增加训练步数。

## 检查与记录

- 训练前：初始预测TV≤1e-5、blind尺度相对误差≤1e-5；读出梯度相对RMS≤1e-3，损失相对
  误差≤1e-5。逐层检查6个普通encoder层有限非零梯度，G2／H1无梯度，随后清除检查梯度。
- 测试用两层真实encoder验证反向能穿过冻结G2；主动切断其输出时，检查必须发现早层断梯度。
  实际优化后G2及H1状态逐值不变，普通encoder与读出确有更新。
- 每100步立即保存汇总和逐对明细。最终及首次拟合checkpoint严格重载后各前向5次，要求
  逐对判定一致，数值TV差≤1e-5；采用上一轮已修复的核验规则，不改变拟合门槛。
- 补充固定32材料的eDOS oracle／blind中位R²与失败率；blind尺度由当前memory经过冻结H1
  重算。纯谱差拟合可能伴随共有谱形漂移，不作为生产准确率晋级依据。
- 新入口`tools/eval/g2_non_value_fit_probe.py`，复用`g2_value_fit_probe`的检查／汇总与
  `g2_small_fit_probe.fit_arm`。新标签`g2_non_value_fit_q1`，setsid + nohup运行，拒绝覆盖。
- 三个旧臂直接引用既有正式结果，保存来源哈希及旧执行版本；仅G2臂既有304行中间逐对明细
  缺失仍如实保留标记，不填补、不重跑。新臂应保存全部21×16＝336行逐对轨迹。

## 下一步边界

- 若本臂通过，下一项建议固定G2参数、只开放最后一个普通encoder层与读出，以进一步收窄
  更新的深度范围；仍需新设计和确认。通过不等于找到信息丢失的具体层。
- 若未通过，先汇总四种更新范围的拟合与稳定性差别，再提出一个针对协同适配或优化稳定性
  的对照，不扫描超参或自动启动全体pilot。
- 本轮仅做这个互补臂，结果写入日志、status和index，不改变默认B7模型或生产数据流程。
