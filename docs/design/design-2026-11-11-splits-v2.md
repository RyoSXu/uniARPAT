## 结论（先看这里）

1. **新数据主要是 eDOS-only**：
   - 新材料中可用的规范 eDOS 有 38,220 个；
   - 新的 phDOS 材料约 8,800 个†（MP 6,819，PhononDB/JARVIS 补充约 2,000）；
   - 两种标签都有的新材料只有 214 个，其中落在旧集合化学式组之外的仅 4 个。
   - 因此"多任务是否有益"的检验只能做成"加入一种谱的单标签数据，看另一种谱是否变好"，见第 5 节。
2. **切分单位改为约分化学式组**（C）。按带盐哈希固定归属（E），新增数据直接归位，不重排。
   - 模拟显示，按 10% / 10% / 80% 分出的新 test / dev / train，在元素、晶系、原子数、元素数上与全体基本一致：任一元素的占比差 ≤ 1.3 个百分点。
3. **旧 valid/test 推荐保留成员不变（选项 C3）**，改为从 train 中移出与它们同化学式组的 1,021 个材料。
   - valid/test 从此与 train 不共享任何约分化学式；代价是 train 少 5.5%。
   - v2 换标签后，新旧数字本来就不可比，所以保留旧集合主要是为了旧 test 的"未参与选型"身份和样本稳定性，不是为了数字连续。
4. **评估集**：
   - 双标签：旧 valid（选型）与旧 test（最终，封存）；
   - eDOS-only：新 dev 与新 test 各约 3,500；
   - phDOS-only：新 test 约 720†；另建议加一个新 phDOS dev（约 710†）。
   - 主指标用 MP 来源，并按来源分开报告。
5. **结构身份（A）**：
   - 按旧数据卡的严格口径，全库不通过的比例为：eDOS 21–30%，声子 68–81%。这主要是弛豫不同，不是材料不同。
   - 按"默认匹配"（同一结构原型）口径：eDOS 0.04%，MP 声子 1.4–3.5%，PhononDB 1%，JARVIS 2%（新条目 14%）。
   - 建议默认匹配不通过的只进 train 并打标记，评估集只收通过的。

## 3. 集合设计

### 3.1 切分单位与规则（C、E）

- **单位**：约分化学式组。同一约分化学式的全部材料（含多晶型、同一材料的不同 MP 编号）只进一个集合。
  - 全库 91,717 组，有标签的新材料中每组平均 1.2 个，中位 1 个。
- **归属**：b = SHA-256(盐 ‖ 约分化学式) 的前 48 位 ÷ 2^48；b < 0.10 → test，0.10 ≤ b < 0.20 → dev，其余 → train。
  - 盐在用户批准时固定并写入清单。
  - 只用化学式计算，与数据到达顺序、标签、模型都无关；以后新增材料直接归位，已有集合不重排。
- **稀有元素**：在有标签的全集中出现于少于 20 个化学式组的元素（目前只有 He、Ne、Ar、Kr），含它们的组一律进 train，避免评估集里出现模型从未见过的元素。只涉及 3 个新材料。

### 3.2 旧集合与新规则的冲突（需用户决定，见末节 D1）

旧切分不是按化学式组划的：

- train–valid 共享 254 组，train–test 253 组，valid–test 44 组；
- 与 valid/test 同组的 train 材料 1,021 个（487 组）；
- valid 中有 345 个、test 中有 351 个材料的化学式在 train 里出现过。

| 选项 | 做法 | 后果 |
|---|---|---|
| C1 原样保留 | 旧三集合不动，新规则只用于新材料 | 最省事；但 valid/test 约 15% 的材料与 train 同化学式，泄漏一直存在，只能另报"干净子集"结果 |
| C2 按新规则重划旧材料 | 旧材料也按哈希重新分配 | 最干净；但旧 test 失去"从未参与选型"的身份（部分进 train），旧 valid 成员大变，旧模型见过的材料会进新评估集；旧 test 曾参与诊断，重划后无法再作封存 test |
| **C3（推荐）保留评估集、清理 train** | 旧 valid/test 成员不变；把与 valid/test 同化学式组的 1,021 个 train 材料移出训练（库中保留并打标记"eval_group_holdout"） | valid/test 与 train 不再共享化学式；旧 test 仍是封存的最终 test；train 少 5.5%。valid–test 共享的 44 组都是评估集，不影响训练 |

- C3 下，新材料若落在旧 valid/test 的化学式组里（有标签的 1,490 个），同样不进训练。
- 建议把它们按组归到对应一侧，作为 eDOS-only 评估的补充（旧 valid 组 → dev 侧，旧 test 组 → 新 test 侧，并封存），单独报告，见 D2。
- 落在旧 train 组里的新材料（4,272 个）直接进 train。

## 4. 评估集规模与分辨力

用 h2 与 h1 在旧 valid 上的逐材料 E（v1 口径；只有这一对相近模型有逐材料导出）估算：两个相近模型的配对差，95% 区间半宽随样本数的平方根缩小。

| 评估集规模 | eDOS 均值差半宽 | eDOS 中位差半宽 | phDOS 均值差半宽 | phDOS 中位差半宽 |
|---:|---:|---:|---:|---:|
| 1,000 | 0.0120 | 0.0077 | 0.0053 | 0.0060 |
| 2,000 | 0.0085 | 0.0054 | 0.0038 | 0.0043 |
| 3,500 | 0.0064 | 0.0041 | 0.0028 | 0.0032 |
| 5,000 | 0.0054 | 0.0034 | 0.0024 | 0.0027 |
| 10,000 | 0.0038 | 0.0024 | 0.0017 | 0.0019 |

- 参照量：h2 的 eDOS E 均值 0.332、中位 0.162；phDOS 均值 0.207、中位 0.130。
- 按上表：新 eDOS dev/test（约 3,500）能分辨约 2% 的相对差。phDOS-only 集（约 700）的半宽约 0.0064，只能分辨约 3% 的相对差；与旧 valid 的 phDOS 合并使用时，约为 1.4%。
- 标签噪声的作用：重复计算中位 0.014、均值 0.204。
  - 它是任何模型都去不掉的误差下限，但对两个模型的配对差影响很小，因为同一条标签的噪声对两者相同。
  - 所以评估集的分辨力主要由模型间的逐材料差异决定，与噪声关系不大。
  - 噪声决定的是"还能改进多少"：v2 下 eDOS 噪声中位约为 h2 v1 中位的 1/10，余量很大。
- v1 与 v2 的尺度不同（C 与标签面积都变了），上表只表示数量级，v2 的值等第 5 步基线出来后重算。

## 5. 分层（只用结构、组成、来源等元信息）

- 模拟的 10/10/80 划分与全体的比较：
  - 晶系各类占比相差 ≤ 1.5 个百分点；
  - 任一元素出现率相差 ≤ 0.9（test）/ 1.3（valid）个百分点，平均 0.26；
  - 元素数分布与原子数中位（13–14）、P90（38–40）一致；
  - 来源占比一致：phDOS 中 MP 约 78%。
- 哈希划分本身已足够均衡，**不建议做强制分层**。强制分层需要按标签以外的变量反复调整，反而引入人为选择。
- 金属/有隙是标签推导量，不用于划分，只在 dev 上事后核对占比。

## 6. 泄漏检查清单（切分后由脚本逐项输出计数）

1. 约分化学式：train 与任一评估集共享的组数必须为 0（C3 下包括旧集合）。
2. 结构近重复：
   - 按约分化学式分组后，同一结构必然同组。
   - 另查不同化学式间的近重复：结构默认匹配通过但化学式不同的情况（如有序/无序近似、超胞化学式），抽查并计数。
3. 同一材料不同 MP 编号：同组，自动处理。
   - 另查 deprecated 编号与当前编号的对应，确保它们不分在两边。
   - 外部条目按 MP 编号映射后，同样随组走。
4. 旧模型/旧检查点见过的材料：
   - 旧 train 与旧 valid 都被旧模型见过，旧 valid 还用于选型。C3 下它们都不进新 test。
   - 新 dev/test 只来自新材料，旧模型从未见过。
   - 旧 test 只参与过诊断，未用于训练或选型。
5. 跨来源重复：
   - 同一材料的 PhononDB/JARVIS 谱与 MP 谱都在库里，但标签只取一条。
   - 同组成的外部条目必然与 MP 材料同组，不会跨集合。
6. 评估集被用于任何选择：
   - 新 test 一旦划定就写入 `sealed/`，和旧 test 一样只输出计数；
   - 本方案的所有统计都没有用到任何 test 标签。

## 7. 与"多任务联合训练是否有益"的对应

新材料几乎没有双标签，所以检验做成"加入单标签数据"的对照：

| 臂 | 训练数据 | 主要看 |
|---|---|---|
| P0 | 旧 train（C3 后，双标签）＋新 phDOS train | phDOS：旧 valid、新 phDOS dev |
| P1 | P0 ＋新 eDOS-only train（27,647，可按哈希取嵌套子集 25% / 50% / 100% 看剂量） | 同上；phDOS 是否随 eDOS 数据增加而变好 |
| E0 | 旧 train ＋新 eDOS train | eDOS：旧 valid、新 eDOS dev |
| E1 | E0 ＋新 phDOS-only train | 同上 |

- **干净性**：新加入的单标签材料按化学式组与所有评估集不相交，所以评估集上的改进不可能来自同化学式记忆，只能来自共享表示。
- **嵌套子集**用固定哈希取，保证 25% ⊂ 50% ⊂ 100%，可以看剂量关系。
- 还可以加一个单任务对照：同样的数据，只训 phDOS 头（eDOS 损失为 0）。它回答"双任务损失本身是否有益"。
  - 这需要训练侧支持部分标签损失（第 8 节）。
- 预算按 Mat2Spec 先做廉价探针（每臂约 15 分钟），有信号再用 h2 配方确认。

4. **来源码与分来源评估**：评估脚本按 `source_*` 分组输出，均值和中位数都报。
5. **视图读取**：`utils/crystal_cache` 已能读 v2 视图；新增的数组（`phdos_modes_per_atom`、来源码、结构标记）要在训练器里显式忽略或使用。

### 需用户决定：部分标签训练时两任务怎么平衡

train 中 eDOS 约 4.5 万条、phDOS 约 2.3 万条（约 2:1），多数行只有一种标签。

| 选项 | 做法 | 后果 |
|---|---|---|
| **W1（推荐）任务内求均值、任务间等权** | 每个任务在 batch 内只对有标签的行求均值，再按 0.5/0.5 相加（与现行协议的 task_weights 相同） | 两任务对梯度的贡献与样本数无关，和当前工作点的设定一致；phDOS 的每条样本权重约为 eDOS 的 2 倍 |
| W2 按标签条数求和 | 所有有标签的项一起求均值 | eDOS 的总影响约为 phDOS 的 2 倍，phDOS 可能变差；与"加数据是否有益"的检验混在一起 |
| W3 按任务重采样 | 每个 batch 中两任务的行数大致相等（phDOS 行过采样） | 等价于 W1，但每轮看到的 phDOS 行更多，训练量随之变化，单任务对照更难对齐 |

- 采样方式：推荐沿用现有的随机打乱，不另做分层采样。
- 多任务对照中，各臂的总步数按"轮数相同"还是"步数相同"对齐，也要在第 5 步方案里写明；推荐按步数对齐，以免数据量不同造成训练量不同。

## 2026-11-12 修改：记录身份与结构判定（替换 D5、D6）

用户在讨论中提出并确认（原话"用他们自己的id也可以吧，jarvis不也有id吗？只要结构-谱是正确的唯一的就可以了吧"；"确实，我们应该做实验来测试"），评审会话整理成下列规则。切分规则（约分化学式分组、哈希 10/10/80、C3）不变。

1. **记录**：每次计算是一条记录，用来源自己的编号（MP 任务号、JARVIS JVASP 号、PhononDB 条目号）。结构与谱取自同一次计算，配套保存。
2. **"同一材料"由结构判定**，MP 编号只作线索，对应关系单独存一张表。
   - 必要条件：约分化学式相同。
   - 判定：默认口径结构匹配通过，且空间群所属的晶系一致。
   - 体积比、匹配后的原子位置偏差作为连续量保存。
   - 编号对应但结构不通过的，到同化学式的其他 MP 材料中找唯一匹配并改挂；能匹配多个或处在阈值边缘的，不连。
