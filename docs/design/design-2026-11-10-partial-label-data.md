# 方案（调研）：2026-11-10 — 多来源、部分标签的谱数据扩充

只读调研与方案，未训练、未改数据契约。执行需用户确认第“需要决定”节。

## 目标与依据

- 2026-11-10 与用户对齐的目标：自主研发的模型，以性能为先，最终做通用的谱性质预测模型（eDOS、phDOS 之外可加入其他谱）。
  外部 uMLIP 只作对照或造数据的“老师”，不作为最终模型的组成部分。
- **数据是当前最大的杠杆**：
  - 学习曲线显示数据翻倍的收益远大于任何架构改动（status）。
  - [结构利用诊断](../logs/log-2026-11-05-structure-use-audit-run.md) 判断主要剩余问题是泛化不足（train/valid 误差差距约 1.7×/2.2×），建议优先扩充数据。
- 现有数据只收录两种谱都有的材料（train 18,706）。如果允许“部分标签”，即一个材料有哪种谱就学哪种谱，可用数据会大幅增加。
  这也是“通用”模型的自然形态：共享结构编码器，每种谱一个输出，各取所需。

## 调研结果

### 1. 坐标查询输出头的历史（2026-09）

| 实验 | 改动 | 结果 |
|---|---|---|
| R1a | Conv1d 头 → 参数匹配的逐点 MLP 头 | 平局（eDOS/phDOS 中位 R² −0.010/−0.010，在 ±0.02 平局线内） |
| R1b | 固定可学习 query＋target → 只由标量坐标 MLP（1→128→512）生成 query，**同时 target 置零** | 失败：中位 R² −0.055/−0.036，Cv MAE +0.16；属组合改动，不能单独归因于坐标 query |
| Q1 / Q2 | 在可学习 query 上加零初始化的坐标残差（普通 MLP / Fourier） | 平局；Q1 已作为当前架构的默认设置 |

依据：[R1b 日志](../../archive/docs/logs/log-2026-09-19-r1b-coordinate-query.md)、[R2 证据审计](../../archive/docs/logs/log-2026-09-26-r2-model-evidence-audit.md)。

**含义：**
- 当前 decoder 已是“每种谱一组可学习 query＋坐标残差”的结构，逐点读出也已证明无害。
- 新增一种谱只需加一组 query 和一个头，不必先改成纯坐标查询。
- 纯坐标查询只在需要任意网格或分辨率时才必要。届时应保留每种谱的可学习部分（如谱类型嵌入＋Fourier 坐标），而不是重复 R1b 的组合。

### 2. 本地已有、未使用的 MP 数据

仓库已忽略的 `tools/data/raw/delta_mp/` 中有 MP 公开 Delta 表，于 2026-11-05 为结构诊断下载：
- `total-dos`：691,978 个计算任务；
- phonon `dos`：pheasy 26,401＋dfpt 1,513 = 27,914 个任务。

两表都带计算结构。按与数据集划分一致的“绝对组成”分组：

| 表 | 任务数 | 组成与 valid/test 相同 | 仅约化组成与 valid/test 相同 | 组成与 train 相同 | **全新组成** |
|---|---:|---:|---:|---:|---:|
| eDOS | 691,978 | 39,470 | 16,844 | 149,832 | **485,832 个任务，90,759 种绝对组成** |
| phDOS | 27,914 | 4,033 | 1,167 | 15,367 | **7,347 个任务，6,721 种绝对组成** |

- 全新组成的 eDOS 任务按泛函分：GGA 307,894、GGA+U 171,736，其余合计约 6,000。81% 的任务不超过 40 个原子。
- 全新组成的 phDOS 任务最多 60 个原子。
- **不需要 MP API 密钥**：表中已有结构，可按结构去重，并按组成排除 valid/test。
- 10-28 盘点和 D3a 所说的“121,420 个候选不在本机”，指的是旧的外部结构目录；这批 task 级数据仍在本地。
- 去重、质量门禁和许可尚未核实，以上只是上限：
  - 一个材料常有多个任务，同一组成也可能有多个多晶型。
  - D3a 的严格可用率约为 53%（[D3a](../../archive/docs/logs/log-2026-09-28-d3a-edos-support-adjudication.md)）。
  - 现有数据集逐材料核实了 BY-C 许可，新任务尚未核实。
- **保守估计**：eDOS 约 5–9 万个新材料，是现有 train 的 3–5 倍；DFT phDOS 约 6–7 千个，约为现有 MP phDOS 的 +40%。

### 3. 合成声子（uMLIP 当老师）

- 阶段 A 的工具可直接用（`tools/data/umlip_phonon_baseline.py`）。
- 实测成本（V100）：
  - 弛豫版平均 8.6 秒/材料；≤20 原子 6.1 秒，≤40 原子 7.8 秒。
  - 不弛豫版 3.2 秒/材料。
- 3 万个材料：弛豫约 70 GPU 小时，不弛豫约 27 小时。
- 结构池可取上节全新组成的 eDOS 结构。
- 质量：relaxed 版对 DFT 标签的 E 为 0.506，频率偏软约 10%。只适合作预训练或辅助信号，不能当作正式标签。
- 有了真实的额外 DFT phDOS（上节约 7 千个）之后，合成声子应排在后面。

### 4. 第三种谱的公开来源（后续）

| 来源 | 规模 | 说明 |
|---|---|---|
| MP X 射线吸收谱（FEFF K 边 XANES） | >50 万条谱，>4 万种材料（2018 数据） | 逐元素、逐吸收位；需 API 密钥；与结构关系密切 |
| JARVIS 光学介电函数（OptB88vdW / TBmBJ） | 2018 年约 1.8 万 / 7 千 | figshare 可下载；JARVIS 排行榜有对应任务 |

来源：[Mathew et al., Sci Data 2018](https://www.osti.gov/pages/servlets/purl/1477360)、[Choudhary et al., Sci Data 2018](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC5944908/)、[JARVIS 数据库文档](https://jarvis-tools.readthedocs.io/en/master/databases.html)。

### 5. 代码现状

- 损失是对整批材料取平均（`model/model.py` 的 `balanced_blind_energy` 分支），`single_task` 是全局开关。
- `edos_mask`/`phdos_mask` 只描述单个箱是否有限，没有“这个材料有没有这种谱”的标记。
- 需要的改动：
  - 数据增加逐材料的任务存在标记；
  - 损失按任务只在有标签的材料上平均；
  - 批采样需保证每批都有两种任务（否则方差大）；
  - 验证、选点和导出保持只在双标签的 valid 上做。
- 几何缓存需为新结构重建：同一工具，新输出目录。

## 计划（2026-11-10 用户答复后更新）

用户答复：
- 新建数据集，格式要更灵活、更丰富；
- 先做 eDOS 和 phDOS，合成声子也纳入；
- MP API 密钥已配置。核验时 summary 接口返回 200，数据库版本 2026.09.28，材料 ID 格式与现有数据集一致。

只有一张 V100，GPU 任务需要排队。

## 对项目审核建议的回应（2026-11-10）

项目审核会话转来 9 条建议（用户同意转交）。用户在审核中补充了两点：研究本意是“通过多任务联合获得更好的效果”；不想在多 seed 上花时间。
以下逐条回应，在 P0 设计中落实；需用户决定的列入下一节。

## 用户决定（2026-11-10，经项目审核会话转达，用户原话“确认，开始吧”）

1. **新 test，封存两块。** 都只取自 MP，在去重和质量门禁之后切分。
   - 双标签 test 约 1,000 条：从 MP 新 phDOS 池按约化组成分组随机取；若过门禁后的池子不足 5 千，降到约 800 条。
   - 只有 eDOS 的 test 约 2,000 条：从 MP 新 eDOS 池取，同样按约化组成分组。
   - 不从 MDR 取 test。
   - 封存方式：ID 清单冻结并记哈希；标签单独存放；加载代码默认拒绝读取，只在定稿时显式打开。切分在新数据上训练任何模型之前完成。
   - 旧 test 保留，定稿时作为次要结果，并注明曾用于诊断。旧 valid 仍是选点用的开发集；另设 eDOS 开发集。
2. **不做 MACE 特征蒸馏，计划中去掉合成声子（P-syn、P4）**。用户原话：“我不太想跟mace相关”。
   MACE＋phonopy 只保留为对比基线；M1（联合 E 0.2618）只作参考线，用来回答“只靠谱数据、不用任何力场，能否追上 MACE 特征的效果”。
3. **Mat2Spec 现在开始移植**，由项目审核会话另起独立会话负责。本会话不做，避免重复。它的正式训练需与 P3 排队，由用户安排。
4. **泛函与来源标记。**
   - 第一轮只用 MP 数据，eDOS 沿用 MP 自己选择规范任务的规则，不启用来源标记。
   - 数据库从一开始就给每条谱记录泛函、计算方法和来源。
   - 模型里的来源标记做成默认关闭的开关。
   - MDR 作为之后单独的一级加入，届时对比开与不开标记；建库时逐条核实各来源的泛函。
   - 其他泛函的数据排在最后，加入时必须开标记。

据此，上面计划表中的 P-syn 与 P4 作废；P5 中的“MACE/MatterSim 参照”只作对比基线。P0 详细设计见 [design-2026-11-10-spectral-store-p0.md](design-2026-11-10-spectral-store-p0.md)。
