# uniARPAT 代码级工程缺陷审查报告

- **审查对象**：`uniARPAT/` 全量核心代码库（`model/`、`datasets/`、`utils/`、`thermo_props.py`、`train.py`、`test.py`、`evaluate_and_plot.py`、`configs/` 等）
- **审查方式**：逐行静态审查 + 数据实测验证（`data/train4ARPAT/*.npy`、`data/*.csv`、`utils/periodic_table_v2.csv`）
- **审查日期**：2026-09-08
- **报告路径**：`uniARPAT/docs/01_开发文档/2026-09-08_uniARPAT_代码级工程缺陷审查报告.md`
- **严重度定义**：`P0=致命（结果错误/崩溃/OOM）`，`P1=严重（精度系统性偏差/显存翻倍/训练失稳）`，`P2=中等（浪费/可维护性/边缘错误）`，`P3=提示（风格/冗余）`

> 结论先行：发现 **P0×7、P1×12、P2×14、P3×6**，共计约 39 项代码级硬伤。
> 最致命的三件事：（1）`mask` 错位 2 列 + `c` 用 `1/c`，几何与掩码双错；（2）Encoder 自注意力“先算一次完整 MHA 再丢弃重算”，且重算分支**未加 padding mask**；（3）Decoder 的 `pos/query_pos` 传入后被完全忽略，`edos_query/phdos_query` 死参。

## 1. 计算冗余与显存浪费（Compute / Memory）

### 1.1 [P0] Encoder 自注意力算两遍，第一遍完全丢弃 — `model/transformer.py:321-349`

**类**：`TransformerEncoderLayer.forward`

```python
# transformer.py:321-323
q, k, v = src, src, src
attn_output, attn_weights = self.self_attn(q, k, v, attn_mask=src_mask, key_padding_mask=src_key_padding_mask)
# ... transformer.py:325-349 紧接着完全不用 attn_output, 而是手工重算 QKV
rp_emb = self.rp_encoder(rel_diss, rel_dirs)          # [B,L,L,d]
rp_emb = self.rp_proj(rp_emb)
q_heads = q.view(B, L, self.nhead, d_model_head)
rp_scores = (q_heads.unsqueeze(2) * rp_emb).sum(-1)   # [B,L,L,nhead]
q_scaled = q / (d_model_head ** 0.5)
q_heads2 = ...reshape(B*nhead, L, d_head)
k_heads = ...reshape(B*nhead, L, d_head)
base_scores = torch.bmm(q_heads2, k_heads.transpose(1, 2))
total_scores = base_scores + rp_scores
attn_weights_new = F.softmax(total_scores, dim=-1)
v_heads = ...reshape(B*nhead, L, d_head)
attn_output_new = torch.bmm(attn_weights_new, v_heads) # [B*nhead,L,d_head]
src2 = attn_output_new                                 # 覆盖, attn_output从未使用
```

**危害**：

- 每层、每步浪费一次完整 `nn.MultiheadAttention`（含 QKV 三个 `d×d` 投影 + `B·h·L²` 注意力矩阵 + 输出投影）。以 `d=512,h=8,L=80,B=32` 计，约浪费 `3·512²≈0.79M` 次 MAC 的投影 + `32·8·80²≈1.64M` 注意力点积 ×6 层，且 `attn_weights [B·h,L,L]` 中间张量白白占用显存与带宽。
- 更糟的是第一遍的 `key_padding_mask` 语义被丢弃（见 §1.3），属于“花钱买错误”。

**修复**：二选一：（A）删除 L323 的 `self.self_attn` 调用，保留手工几何偏置分支并补 mask（见 §1.3）；（B）改用 `torch.nn.functional.scaled_dot_product_attention` 并将 `rp_scores` 作为 `attn_mask` 传入，避免手写 reshape/bmm。若保留 `self.self_attn` 模块仅为占位，应删除该子模块以节省优化器状态。

### 1.2 [P0] 相对几何编码每层重复计算 + 超大 `[B,L,L,d]` 中间张量 — `model/transformer.py:142,304-311,325-331` + `utils/rp_encoding.py:30-38`

**涉及**：`Transformer.forward:142`、`TransformerEncoderLayer.__init__:304-311`、`forward:325-326`、`RPEncoding.forward`

```python
# transformer.py:142 每个forward算一次 distances[B,L,L], unit_dirs[B,L,L,3]
distances, unit_dirs = compute_relative_features(pos)
# ... Encoder每层又各算一次:
rp_emb = self.rp_encoder(rel_diss, rel_dirs)  # RBF[ B,L,L,64 ] × 球谐[ B,L,L,9 ] →外积[B,L,L,576]
rp_emb = self.rp_proj(rp_emb)                 # [B,L,L,512]
```

- `distances/unit_dirs` 对 6 个 Encoder 层完全相同，却在每层重新做 `RBF⊗Ylm` 外积。`RPEncoding(lmax=2)` 的 `out_dim=64·9=576`，中间 `con[B,L,L,64,9]` 以 `B=32,L=80` 计为 `32·80·80·576≈117.96M` 元素，FP32 约 **472MB/层**，6 层顺序执行虽可复用但峰值 + 带宽极高，是实测 VRAM 爆涨的主因之一。
- `q_heads.unsqueeze(2)*rp_emb` 的广播乘法同样为 `[B,L,L,h,d_h]` 量级（`32·80·80·8·64≈104.8M` 元素，约 400MB），且保留梯度用于反向， Tomas显存翻倍。
- `e3nn.o3.spherical_harmonics(..., directions)` 对 `L²` 个方向向量逐层调用，对角线 `i==j` 处 `direction=0` 向量（见 `utils/relative_features.py:67` 的 `0/(0+1e-8)=0`）是球谐的奇点，`normalize=True` 下可能产生 NaN/非预期常数（见 §4.6）。

**修复**：

1. 将 `RPEncoding` 的 `RBF⊗Ylm` 提升到 `Transformer.forward` 算一次并缓存，多层共享；或至少按层缓存 `rbf/sph` 只投影不同。
2. 避免物化 `[B,L,L,576]`：先将 `rbf[B,L,L,64]` 用小矩阵降维，或将点积改写为 `(q·W)·φ(d,Ω)` 的低秩形式；大 `L` 时按 `i` 分块（chunked attention bias）。
3. 对角线 `mask.fill_diagonal_` 将自对距离/方向置零或 mask 掉，并在 `RPEncoding` 入口 `clamp` 零向量。
4. 若暂不重构，至少在 `run_pilot_10epochs.py:84` 记录的峰值 VRAM 旁加断言，防止 `B=32,L=80` 在 16GB 卡上 OOM。

### 1.3 [P0] 手工注意力分数未加 `key_padding_mask`，padding 参与 softmax — `model/transformer.py:339-341`

```python
total_scores = base_scores + rp_scores
attn_weights_new = F.softmax(total_scores, dim=-1)  # 无任何 -inf mask
```

`src_key_padding_mask=mask_atom` 只传给了已被丢弃的 L323 的 `self_attn`，真正生效的 `total_scores` 没有任何 mask。后果：短晶体后部的大量零 padding（`N` 中位数 8，`L=80`，约 90% 为 pad）以全权重参与加权平均，`memory` 被稀释；`global_masked_pool` 虽然 mask 了池化，但 `memory` 本身已被污染，池化无法挽回。

**修复**：

```python
if src_key_padding_mask is not None:
    mask_exp = src_key_padding_mask.view(B,1,1,L).expand(B,self.nhead,L,L).reshape(B*self.nhead,L,L)
    total_scores = total_scores.masked_fill(mask_exp, float('-inf'))
attn_weights_new = F.softmax(total_scores, dim=-1)
```

并补单元测试：构造 `N=2` + 78 pad 的 batch，断言 pad 列权重和为 0。

### 1.4 [P1] `RBFEncoding/rel_proj/dir_proj` 初始化了但从未使用 — `model/transformer.py:304-308`

```python
self.rbf_encoder = RBFEncoding(num_centers=64, cutoff=10.0)  # 从未被forward引用
self.rel_proj = nn.Linear(self.rbf_encoder.num_centers, d_model)
self.max_ell = 3
dim_sph = sum([2*l+1 for l in range(self.max_ell+1)])  # 16
self.dir_proj = nn.Linear(dim_sph, d_model)           # 从未使用; 且16与RP实际9维不一致
```

### 1.5 [P1] 同一 `self.decoder` 被串行调用两次，无法并行且 Key/Value 重复投影 — `model/transformer.py:175-186`

```python
hs_edos, _ = self.decoder(edos_tgt_input, memory, ...)   # 128 queries
hs_phdos, _ = self.decoder(phdos_tgt_input, memory, ...) # 64 queries, 同一权重
```

共享 Decoder（`decoupled_decoder=False` 的 M1 基线）对同一 `memory` 做两次完整的 6 层解码，`memory` 的 K/V 投影被重复计算两次（各 `6·2·d²`）。`edos(128)+phdos(64)=192` queries 本可 concat 成一次前向（`[B,192,d]`），自注意力为块对角（或允许 eDOS↔phDOS 交互，视设计而定），至少 K/V 投影可复用。

**修复**：将两次调用合并为一次（拼接 queries，一次 cross-attn），或在 `decoupled_decoder=False` 时明确注释“参数共享但计算量×2”，并在消融报告中剔除该混杂因子（M1 的 77.6M vs M2 的 73.0M 差异部分来自此处）。

### 1.6 [P2] `safe_shape_norm` 的 fallback 分支每步都算 — `model/transformer.py:17-28,200-202`

```python
pos = F.relu(z)
fallback = F.softplus(z)  # 无论是否需要都计算, [B,128]+[B,64]
return torch.where(max_val > 1e-4, pos/(max_val+1e-6), fallback/(fallback_max+1e-6))
```

`softplus` 含 `exp`，开销约为 ReLU 的数倍，且正常训练 `max_val>1e-4` 恒成立（随机初始化后几乎不可能全负），属于常驻浪费。另 `torch.where` 在阈值处不可微（见 §4.3）。

**修复**：先判 `need_fallback = (max_val <= 1e-4).any()`，仅当需要时才算 softplus；或彻底改用 `softplus` 单分支 + `max` 归一（见 §4.3 建议）。

### 1.8 [P2] `data_preprocess` 12 次独立 H2D + mask 两次搬运 — `model/model.py:102-130`

```python
mask = (inp == 0)                       # CPU上算
inp = inp.to(device, non_blocking=True) # 12次独立.to()
...
mask = mask.clone().detach().to(dtype=torch.bool, device=device)
```

- 每个 batch 触发 12+1 次 H2D 同步；`pin_memory=True` 的优势被分散小拷贝抵消。

### 1.9 [P2] DataLoader `prefetch_factor=10 × num_workers=1` 常驻多 batch 显存/内存 — `configs/config.yaml:53-57`

```yaml
dataloader: {num_workers: 1, pin_memory: True, prefetch_factor: 10, persistent_workers: True}
```

单个 worker 预取 10 个 batch（`10·32·(82+246+192)·4B≈0.6MB` 数据本身不大，但连同 `relative_features` 的 `[B,L,L,3]` 中间量 + Python 队列会放大常驻内存），且 `persistent_workers=True` 在 10-epoch pilot 中使 worker 常驻。收益几乎为零（瓶颈在 GPU 的 `RPEncoding+e3nn`，而非 IO）。

**修复**：`prefetch_factor: 2`，`num_workers` 按 `per_cpus` 覆盖时同步调小 prefetch；IO 不是瓶颈时关闭 `persistent_workers`。

## 2. 死代码与未生效参数（Dead Code / No-op Params）

### 2.1 [P0] Decoder 的 `pos/query_pos` 传入后被完全忽略，`edos_query/phdos_query` 为死参 — `model/transformer.py:161-186,377-399`

**调用侧**（`Transformer.forward`）：

```python
# transformer.py:156-159,162-186
edos_query = self.edos_query_embed.unsqueeze(0).repeat(B,1,1)  # [B,128,512]
...
hs_edos,_ = self.edos_decoder(edos_tgt_input, memory, memory_key_padding_mask=mask_atom, pos=pos, query_pos=edos_query)
```

**实现侧**（`TransformerDecoderLayer.forward:377-399`）：签名接收 `pos/query_pos`，但函数体内**一次都没用**：

```python
def forward(self, tgt, memory, tgt_mask=None, memory_mask=None, tgt_key_padding_mask=None,
            memory_key_padding_mask=None, pos=None, query_pos=None):
    q = tgt; k = tgt
    tgt2 = self.self_attn(q, k, value=tgt, ...)[0]   # 未加 query_pos
    ...
    tgt2, attention_v = self.multihead_attn(query=q, key=memory, value=memory, ...)  # 未加 pos
```

DETR 式 Decoder 本应 `q = tgt+query_pos, k = memory+pos`，此处两者皆无。后果：

- `edos_query_embed[128,512]`、`phdos_query_embed[64,512]` 共 `192·512≈98k` 参数梯度恒为 0（从未参与计算图），AdamW 仍为其维护动量，白白占用优化器状态并污染参数量统计。
- eDOS/phDOS 双分支的绝对能量/频率位置信息只能靠 `edos_tgt/phdos_tgt` 的内容区分，跨 bin 的平移等变性假设（Conv Head，见 §3.5）失去显式位置锚点。

**修复**（按 DETR 范式）：

```python
q = tgt + query_pos if query_pos is not None else tgt
# cross: query=q, key=memory (+pos_proj if dense pos), value=memory
```

或删除 `query_pos/pos` 参数与 `*_query_embed` 参数，二选一，不要“定义+传递+忽略”三连。

### 2.2 [P0] Padding mask 错位 2 列：`mask[:, :atom_len]` 含哨兵、丢尾部 — `model/transformer.py:124-126` + `model/model.py:108,126,196-198` + `model/heads.py:133-143`

数据布局（`data/csv2npy.py:26-28` + 实测）：`elements/positions` 长度 82 = 2（晶格行：`126,127` / `(a,b,1/c),(α,β,γ)`）+ 80（原子）。`Transformer.forward` 正确用 `src[:,2:]` 剥离哨兵取原子：

```python
# transformer.py:124-129
B, Lp, _ = pos.shape          # Lp=82
atom_len = Lp - 2             # 80
mask_atom = mask[:, :atom_len]  # BUG: 取前80列=[哨兵0,哨兵1,原子0..77], 丢了原子78,79
atom_idx = src[:, 2:]           # 正确: [原子0..79]
```

`mask` 来自 `model/model.py:108 mask=(inp==0)`，`inp` 为 `elements[B,82]`，前 2 列恒为 `126,127`（非零→mask=False=valid）。于是：

- `mask_atom` 的前 2 列恒 valid，却被对齐到 `memory` 的前 2 个**真实原子**（错位但恰好同为 valid，短晶体头部侥幸无感）；
- 真正有害的是尾部：原子 78,79 的 padding 状态被丢弃，**恒被当作有效原子**参与编码器自注意力（§1.3 又无 mask，双重失效）、`global_masked_pool` 平均（分母偏大，晶体向量被稀释）、`model.py:197 valid_atoms=(~mask[:,:atom_len]).sum()` 多算 2 个哨兵（`valid_atoms = 2 + valid(原子0..77)`，对 `N≤78` 的样本恒**多 2**，占比 10965 个中的绝大多数，中位数 N=8 时 `3N` 求和规则目标被抬高 33%）。

**修复**：全仓统一改为 `mask_atom = mask[:, 2:2+atom_len]`（或 `mask[:,2:]`），并对 `model.py:197`、`heads.py:140` 的池化/计数同步修复，加回归测试：`N=1` 的单原子晶体 `valid_atoms==1` 且 `memory` 尾部零向量权重为 0。

### 2.3 [P1] AMP `GradScaler` 初始化了但从未 `scale/step/update`，且前向无 `autocast` — `model/model.py:11,50,209-212,440,456,468`

```python
# model.py:50
self.gscaler = amp.GradScaler(init_scale=1024, growth_interval=2000)
# model.py:209-212 实际训练:
self.optimizer[...].zero_grad()
total_loss.backward()          # 裸backward
self.optimizer[...].step()     # 裸step, 无scaler
# 但 checkpoint 却保存/加载 amp_scaler 状态 (440,456,468)
```

- `torch.cuda.amp` 在新版 torch 已迁移到 `torch.amp`（`import torch.cuda.amp as amp` 会告警，`requirements.txt:2 torch>=2.2.0` 下行为不保证）。
- `init_scale=1024` 远小于默认 65536，若将来打开 AMP，`growth_interval=2000` 又过大，溢出后恢复极慢；当前则是“存了个从未更新过的 scaler”，`checkpoint_best.pth` 中的 `amp_scaler` 字段恒为初值，恢复训练时产生“已恢复 AMP 状态”的假象。
- 全程 FP32 训练本身不是 Bug，但与“数值稳定性与 AMP 溢出隐患”的审查要求对照：RBF `exp`、Pearson 除法、求和规则除法（见 §4）都没有在 AMP 下的防护，一旦打开 AMP 即溢出。

**修复**：要么删除 `gscaler` 及 checkpoint 相关字段（诚实 FP32），要么完整接入：`with torch.autocast(device_type='cuda', dtype=torch.float16/bfloat16): outputs=...; loss=...` + `scaler.scale(loss).backward(); scaler.step(opt); scaler.update()`，并将 `init_scale` 改回默认或按 loss 尺度重调。

### 2.4 [P1] `Transformer._reset_parameters` 用 Xavier 覆盖了全部 `dim>1` 参数，破坏零初始化意图 — `model/transformer.py:91,117-120,108-112`

```python
def _reset_parameters(self):
```

## 4. 数值稳定性与物理口径（Stability / Physics）

### 4.1 [P0] `edos_max` 钳制 `500` 与 `log(max)` 尺度监督冲突，且 4 个超界样本被静默截断 — `model/model.py:172-176`

实测 `edos per-sample max` 最大 10618，`>500` 占 4/10965。`log(10618)=9.27` 被钳到 `log(500)=6.21`，单样本尺度标签偏差 3.06（Huber 的 β=1 外已是线性区，梯度恒 1），模型被迫低估高峰材料。同时 `init bias 3.0→exp=20.08`（中位数 19.5，合理）对高峰样本初始低估 500×，`0.5·Huber` 权重下需数十 epoch 才爬升。

**修复**：删除 `max=500`（或改成分位数 winsorize + 样本权重），或改用 `log1p(max)/log(分位数)` 稳健尺度；`scale` 分支改预测 `log(分位数)+log(峰形因子)` 解耦。

### 4.2 [P0] M5 的 `out_edos/out_phdos` 原始幅度无约束，`shape` 归一化使其尺度不变 — `model/transformer.py:193-202` + `model/model.py:164-207`

`train_one_step` 的 M5 分支只监督 `shape(归一化)+log_scale+gap+sum`，**从不直接监督 `out_edos` 本体**。而 `shape=safe_shape_norm(out)` 对 `out` 的整体仿射 `a·out+b(a>0)` 近似不变（ReLU+max 归一），`out` 可漂移到 `±1e4` 而 `shape` 不变。后果：`out` 缓慢漂移→FP16 下溢/上溢（若开 AMP）、`safe_shape_norm` 的 `max+1e-6` 相对精度丢失、`evaluate_and_plot.py:79-80` 若误用 `outputs['edos']`（原始 `out`）而非 `phys_*` 则数值完全不对（实测该文件确实用错，见 §5.2）。

**修复**：给 `out` 加弱正则 `1e-4·mean(out²)`，或让 Head 直接输出 `shape`（`softplus` 约束）而非无界值再归一；`evaluate` 统一用 `phys_*`。

### 4.3 [P1] `compute_shape_loss` 的 Pearson+分支切换在平坦谱处不连续 — `model/model.py:15-31`

```python
var_tgt = torch.mean(tgt_diff**2, dim=-1)          # 方差
r = cov/(std_p*std_t+1e-8)                          # 双重eps: sqrt内+1e-8, 分母再+1e-8
loss = where(var_tgt<1e-4, mse, (1-r)+0.5*mse)      # 硬切换, 不可微边界
```

- `1e-4` 对 `[0,1]` shape 空间对应 `std=0.01`，带隙绝缘体的带隙区 + 尖峰谱的方差恰在此附近抖动，`where` 导致 loss 在阈值两侧跳变（`1-r∈[0,2]` vs `mse∈[0,1]` 量级不同），梯度方差增大。
- `std=sqrt(sum+1e-8)` 对 `L=128` 的平坦谱，`sum≈0` 时 `std≈1e-4`，`r≈cov/1e-8` 放大噪声；虽有 `flat_mask` 兜底，但阈值附近样本的 `r` 仍可能 `±1` 震荡。
- `total_loss=shape_e+3.0·shape_p+0.5·(scale)+0.2·gap+0.1·sum`（L201）的 `3.0/0.5/0.2/0.1` 为手设，无不确定性加权，`shape_p` 主导，`gap/sum` 物理约束几乎无声。

**修复**：`loss = (1-r) + 0.5·mse` 单分支 + `r` 用 `clamp(std,min=1e-3)` 稳健化，或改用 `1-r²` 有界形式；多任务权重改 `uncertainty weighting` 或至少按 running variance 归一；`flat` 样本改 `mse` 权重渐变（sigmoid(var)）而非硬 `where`。

### 4.4 [P1] 归一化统计量在变换**前**计算，`dos_minmax/zscore/log/scale` 组合即错 — `datasets/dataset.py:25-49` vs `model/model.py:257-307`
