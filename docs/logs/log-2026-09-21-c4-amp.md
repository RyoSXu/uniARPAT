# 工作日志 2026-09-21：C4 CUDA 自动混合精度门禁

## 范围

- **目标：**为后续 Q1 试验提供可选的 CUDA FP16 自动混合精度（AMP）载体，降低资源成本；不将其作为准确率候选。
- **唯一变量：**`--use_amp`（默认关闭）。开启时 transformer 前向使用 FP16 `autocast`，输出在 SumNorm 损失、物理反归一化和指标前转换回 FP32；反向使用动态 `GradScaler`。模型、B7 checkpoint、Q1 batch、损失、优化器、随机种子均不变。
- **边界：**不读 test split，不训练 epoch；资源门禁的 20 个训练步只用于数值、scaler 和成本测量。

## 证据

- 实现：`ExperimentConfig`、runner 和 `basemodel` 接入 `use_amp`；关闭路径保留原 `backward → step`，AMP 路径为 `scale → backward → unscale（若裁剪）→ step → update`。runner 将 `use_amp` 写入有效配置和 checkpoint，并拒绝以不同 AMP 设置恢复 checkpoint。
- CPU 合同：默认关闭与显式 `False` 的输出逐元素一致；CPU 上 `use_amp=True` 显式报错，不静默降级。
- V100 资源命令：

  ```bash
  python3 tools/eval/c4_amp_resource_gate.py
  python3 -m unittest discover tests
  ```

  使用 B7 `_e9ctl` epoch 33、Q1 train 的同一真实 batch 32；每臂 warm-up 3 步后测量 20 步。

| 指标 | FP32 | AMP | AMP / FP32 |
|---|---:|---:|---:|
| 平均训练步耗时 | 329.80 ms | 150.62 ms | 0.457× |
| 峰值显存 | 7,421 MB | 7,044 MB | 0.949× |

- AMP 与 FP32 的归一化概率平均／最大绝对差：eDOS `3.60e-6 / 1.54e-4`，phDOS `7.43e-6 / 3.42e-4`，均在预注册的 `1e-4 / 2e-3` 门限内。所有 20 步损失、梯度和更新后参数有限；scaler 的 growth tracker 从 3 增至 23，说明它实际参与了更新。
- 全套 **80/80** 测试通过。机器可读证据为 `results/c4_amp_resource_v100.{json,csv}`。

## 结论

- **状态：技术通过。**C4 `--use_amp` 可作为后续训练的低成本可选载体；它不改变 B7 的 FP32 默认、不产生 accuracy 结论，也不能与 FP32 checkpoint 混合恢复。
- V100 上资源收益主要来自吞吐（−54.3% 单步时间）；显存仅降低 5.1%，因此它不授权提高 batch size，除非另立单因素资源设计。
