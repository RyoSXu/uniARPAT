## 1. 架构收敛与工程原则

### 1.1 核心网络拓扑定型（M4 鲁棒主干 + M3 备选开关）
根据 Week-2 验收报告 §6 补正，uniARPAT-v2 采用层次化多任务架构（以下为 M4 实测参数拆分，总计 75.85M，与 `ablation_train.log` Verified 参数一致）：
1. **Shared Encoder (20.94M)**：6 层 Transformer Encoder 深度共享，学习贴近玻恩-奥本海默势能面的底层晶体表征；另含 `tok_emb` 0.060M + `num_emb` 0.002M + `fuse_proj` 0.525M 及 LayerNorm 余量；
2. **Decoupled Decoders (各 25.23M)**：电子任务（128 个可学习 Query）与声子任务（64 个可学习 Query）各配 6 层独立 Decoder，拥有完全独立的语义解码空间，消除单一解码器的模态争抢（解码器合计 50.45M，为全网主体，原 Rev 3.0 “各 3.8M”系笔误已废止）；
3. **Zero-Init Gated Cross-Attention (M4 核心，2.10M)**：在双解码器输出端建立双向信息流。零初始化门控权重（$\alpha_e, \alpha_p = 0$）确保初始不干扰解耦表征，训练中自主传递物理边界约束，将声子预测失败率压制在 5.40%；在配置文件中设置 `use_gated_cross_attn: true/false`，允许用户一键切换至 M3 精度优先分支；
4. **Capacity-Symmetric Heads (对称多层投射)**：eDOS 与 phDOS 均使用 3 层 MLP（d_model $\to$ 1024 $\to$ 512 $\to$ out_dim），每层包含 LayerNorm 与 GELU 激活，参数量各 0.788M，彻底解放电子态密度的拟合上限。

### 1.2 损失函数重构：回归纯端到端直接回归
废弃 M5 脆弱的多目标分立损失（5 项复合损失撕扯、尺度平方放大误差），重构为物理直观、数值稳健的 **直接回归损失（Smooth-L1 / Huber Loss）**：
$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{smooth\_l1}}(\hat{y}_{\text{edos}}, y_{\text{edos}}) + \lambda_{\text{ph}} \cdot \mathcal{L}_{\text{smooth\_l1}}(\hat{y}_{\text{phdos}}, y_{\text{phdos}})$$
* $\lambda_{\text{ph}} = 1.0$（标准化空间下等权平衡）；
* Smooth-L1 在小残差处呈二次方平滑梯度，在大残差离群点处呈线性梯度，天然防止尺度扰动引发数值崩溃。

## 2. 四大 P0 级工程缺陷修复规格（Code Diff Specifications）

### 2.1 FIX-P0-01：根治 Padding Mask 2 列错位（数据污染修复）
- **问题文件**：[`model/transformer.py:125-126`](file:///root/home/newstudy/uniARPAT/model/transformer.py#L125-L126) 与同病 [`model/model.py:197`](file:///root/home/newstudy/uniARPAT/model/model.py#L197)（M5 求和规则 `valid_atoms` 同样误用 `mask[:, :atom_len]`，必须同批修复，否则原子数统计持续偏置）
- **病灶机理**：输入元素张量 `src` 长度 82，前 2 位为哨兵 `[126, 127]`，后 80 位为原子序数。原代码取 `atom_idx = src[:, 2:]`（长度 80），但掩码却截取了 `mask_atom = mask[:, :atom_len]`（即 `mask[:, 0:80]`），导致掩码相对原子发生了 **整整 2 列的左移错位**！真实前 2 个原子被赋予哨兵的 `False` 掩码，而真实后 2 个有效原子被截断赋予 `True` 误杀。`mask = (inp == 0)` 语义下哨兵永为 `False`，padding 才为 `True`，错位后污染是确定性的。
- **改动代码**：
```python
# Before (transformer.py:125-126, model.py:197 同理)
atom_len = Lp - 2
mask_atom = mask[:, :atom_len]

# After (FIX-P0-01，两处同改)
atom_len = Lp - 2
mask_atom = mask[:, 2:2 + atom_len]  # 严格对齐 src[:, 2:] 剥离哨兵后的原子区间
# model.py:197 同步改为：
valid_atoms = (~mask[:, 2:2 + atom_len]).sum(dim=-1).float()
```

### 2.2 FIX-P0-02：晶格 $1/c$ 倒数反解与真实实空间三维几何复原
- **问题文件**：[`utils/relative_features.py:17-37`](file:///root/home/newstudy/uniARPAT/utils/relative_features.py#L17-L37) 与 [`test_cif.py:60-66`](file:///root/home/newstudy/uniARPAT/test_cif.py#L60-L66)
- **病灶机理**：`position.csv` 历史格式中第 3 列存储的是 $1/c$ 归一化特征。原 `build_cell_from_lattice` 直接将 $0.15 \sim 0.2$ Å 当作边长 $c$ 构造 3x3 晶胞矩阵，导致 $z$ 轴距离被严重压缩 36 倍，RBF 几何编码感受野彻底错位；而推理脚本 `test_cif.py` 却塞入真实 $c$ 边长，导致训练与推理分布撕裂。
- **改动代码 (`utils/relative_features.py`)**：
```python
# Before (relative_features.py:17-19)
abc    = pos[:,0]       # [B,3]
angles = pos[:,1]       # [B,3]
a, b, c = abc.unbind(dim=1)

# After (FIX-P0-02)
abc    = pos[:, 0]       # [B, 3] = (a, b, inv_c) 归一化特征契约
angles = pos[:, 1]       # [B, 3] = (alpha, beta, gamma) 单位度
a = abc[:, 0]
b = abc[:, 1]
# FIX-P0-02: 第三列存的是 1/c 归一化特征，必须倒数还原为真实实空间晶格常数 c
inv_c = abc[:, 2].clamp(min=1e-4)
c = 1.0 / inv_c

# 防御性物理断言：过滤非法晶格常数
assert ((a > 0.5) & (a < 60) & (b > 0.5) & (b < 60) & (c > 0.5) & (c < 60)).all(), \
    f"Illegal lattice parameters detected: a_min={a.min()}, b_min={b.min()}, c_min={c.min()}"
```

### 2.3 FIX-P0-03：剔除 Encoder 冗余 MHA 计算并注入 Padding Mask
- **问题文件**：[`model/transformer.py:320-345`](file:///root/home/newstudy/uniARPAT/model/transformer.py#L320-L345)
- **病灶机理**：在 `TransformerEncoderLayer.forward` 中，代码先执行了 `attn_output, attn_weights = self.self_attn(...)`，紧接着弃之不用，又手写了一遍 `base_scores + rp_scores` 重新做 `bmm`。这导致每次 forward 浪费了大量 FLOPs 和显存；更致命的是，手写重算的 `total_scores` 分支**遗漏了 `src_key_padding_mask`**，使得 padding 原子向有效原子泄露了注意力权重。
- **改动代码 (`model/transformer.py`)**：
```python
# Before (transformer.py:321-342)
q, k, v = src, src, src
attn_output, attn_weights = self.self_attn(q, k, v, attn_mask=src_mask, key_padding_mask=src_key_padding_mask)
...
total_scores = base_scores + rp_scores
attn_weights_new = F.softmax(total_scores, dim=-1)

# After (FIX-P0-03)
# 1. 彻底删除 self.self_attn 的无用调用，释放额外算力
q, k, v = src, src, src
...
total_scores = base_scores + rp_scores  # [B * nhead, L, L]

# 2. 将 src_key_padding_mask 正确注入重算打分中（阻断 padding 污染）
if src_key_padding_mask is not None:
    # src_key_padding_mask: [B, L] -> [B * nhead, L, L]，其中 L = src.size(1)
    # 注意：必须用 -1e9 而非 float('-inf')，否则全 padding 行经 softmax 会产生 NaN
    B_, L_ = src.size(0), src.size(1)
    mask_expanded = src_key_padding_mask.unsqueeze(1).unsqueeze(2)  # [B, 1, 1, L]
    mask_expanded = mask_expanded.repeat(1, self.nhead, L_, 1).view(B_ * self.nhead, L_, L_)
    total_scores = total_scores.masked_fill(mask_expanded, -1e9)

attn_weights_new = F.softmax(total_scores, dim=-1)
```

### 2.4 FIX-P0-04：接通 Decoder 死参 `query_pos`（条件查询激活）
- **问题文件**：[`model/transformer.py:382-395`](file:///root/home/newstudy/uniARPAT/model/transformer.py#L382-L395)
- **病灶机理**：`TransformerDecoderLayer.forward` 的形参中接收了 `query_pos`，但在函数体内 `q = tgt; k = tgt` 以及 `q = tgt; k = memory` 时，**完全没有将 `query_pos` 加入 `q` 或 `k`**。实测反向后 `edos_query_embed.grad is None`、`phdos_query_embed.grad is None`（根本不在计算图，而非梯度为 0），`edos_tgt` 梯度正常，证实为死参数，无法对能谱查询向量施加能量位置条件。
- **改动代码 (`model/transformer.py`)**：
```python
# Before (transformer.py:384-393)
q = tgt
k = tgt
tgt2 = self.self_attn(q, k, value=tgt, ...)[0]
...
q = tgt
k = memory
tgt2, attention_v = self.multihead_attn(query=q, key=memory, value=memory, ...)

# After (FIX-P0-04)
# 在 Self-Attention 中注入 query_pos (类似 DETR 标准设计)
q = tgt if query_pos is None else tgt + query_pos
k = tgt if query_pos is None else tgt + query_pos
tgt2 = self.self_attn(query=q, key=k, value=tgt, attn_mask=tgt_mask, 
                      key_padding_mask=tgt_key_padding_mask)[0]
tgt = tgt + self.dropout1(tgt2)
tgt = self.norm1(tgt)

# 在 Cross-Attention 中注入 query_pos
q = tgt if query_pos is None else tgt + query_pos
k = memory  # 若未来扩展晶格位置，此处可为 memory + pos
tgt2, attention_v = self.multihead_attn(query=q, key=k, value=memory,
                                        attn_mask=memory_mask,
                                        key_padding_mask=memory_key_padding_mask)
```

## 3. 交付级纯端到端工具开发：`cif2dos.py`

彻底废除遗留的 `test_cif.py`，开发一体化生产级命令行工具与 Python API：

### 3.1 命令行交互规范
```bash
# 单文件端到端预测 (自动输出 eDOS, phDOS, Cv, kappa_L 与多子图)
python cif2dos.py --cif ./examples/Si.cif --weights ./checkpoints/uniarpat_v2_best.pth --output ./results/Si_output

# 批量预测整目录
python cif2dos.py --cif_dir ./my_crystals/ --weights ./checkpoints/uniarpat_v2_best.pth --output ./batch_results/
```

### 3.2 核心流程与功能矩阵
1. **纯净 Pymatgen 解析**：原生读取 `.cif`，提取晶格向量 $(a,b,c,\alpha,\beta,\gamma)$ 与分数坐标；严格按照特征契约自动将 $c$ 编码为 $1/c$ 输入模型；
2. **零 Oracle 纯自主推理**：单次前向传递，同时输出物理量纲的 128 维 eDOS ($E - E_F \in [-10, 10]\text{ eV}$) 与 64 维 phDOS ($\omega \in [-280, 980]\text{ cm}^{-1}$)；
3. **宏观物性自动联动计算**：
   - 自动调用内置的 Julian-Slack 计算室温热导率 $\kappa_L(300\text{ K})$；
   - 自动进行玻色-爱因斯坦积分计算全温区热容 $C_v(T)$ 与德拜温度 $\Theta_D$；
4. **出版级图形自动输出**：导出包含“晶体结构投影 + eDOS 费米面对齐图 + phDOS 谱线图 + $C_v(T)$ 连续曲线”的四联出版级图表（PNG & PDF 矢量格式）。
