# 设计：C5 token 级 decoder MoE（park）

> 对应 `docs/status.md` 的当前关卡。设计被接受、搁置或退役时同步更新该项状态。

> **结果（2026-09-18）：**M1×10 的 Q1 oracle 结果为平局且无 win；默认关闭，不做 35 epoch 确认。

## 目标与成功判据

- **假设：**同一套 decoder 前馈网络不足以同时处理谱中的尖峰、平坦区及不同任务的局部表示；让每个
  eDOS/phDOS token 从多个专家中选择计算，可改善谱形预测。
- **对照：**新跑的 M1×10 `_c5ctl`，Q1、E0/P0、SumNorm KL/W1/Huber、H1 eta/gamma、0.05
  dropout、seed 42 和其余训练配方完全一致。
- **实验臂：**M1×10 `_c5tok`，只开启 C5。主指标为 oracle 测试集 eDOS/phDOS 中位 R²与失败率；
  同时记录验证集、blind 指标、oracle–blind gap、每 epoch 时间和峰值显存。
- **判决：**若至少一个任务跨过平局线（中位 R²提升至少 0.02），且任一任务的失败率未恶化超过 1
  个百分点、另一个任务没有有害退化，则为 win 并进入 M1×35 等算力确认；否则 C5 park，默认关闭。

## 改动

- 单一因素为 decoder 内的 token 级专家分工；不改变数据、网格、窗口、bin、输出卷积头、损失形态、
  H1 或 CIF 输入约定。
- 仅在共享 decoder 的最后两层、其 cross-attention 后的前馈位置加入残差 MoE。每个 eDOS/phDOS
  token 使用同一个共享路由器，在 4 个 `512→768→512` GELU 专家中选 Top-2，并按归一化门权重合成。
- 保留原前馈网络；MoE 通过零初始化残差系数加入，所以从 B7 权重迁移时 C5 初始输出严格等于 B7。
  这也使关闭路径保持原 M1 状态字典与输出合同。
- 增加固定权重 0.01 的负载均衡项，使路由概率和实际 Top-2 分派均趋向均匀。它是 MoE 机制的一部分，
  不单独扫描。
- 新增参数为 `2×4×(512×768+768×512+768+512)` 加两个路由器，约 6.31M，小于 8M 上限。

## 测试关卡

1. `--c5_moe` 默认关闭；关闭时不新增参数，且现有单测保持通过。
2. 小模型测试 Top-2 只选择两个专家、门权重归一、负载项有限且对路由器有梯度。
3. 将共同权重从关闭模型迁移到开启模型后，零残差下 eDOS/phDOS 输出逐元素相等；MoE 系数获得梯度，
   随后专家参数可获得梯度。
4. 断言 M1 的新增参数不超过 8M；CPU 单步真实数据冒烟必须产生有限的总损失和 C5 负载项。

## 成本与风险

- 两个后层会额外计算所选的两个专家，预计训练时间与显存上升；pilot 记录实测成本，不以预期替代。
- Top-2 可能发生专家塌缩；负载均衡、每 epoch 专家使用率记录和失败即 park 用于识别该风险。
- C5 不解决非均匀网格；坐标条件非卷积读出和网格数据表示是 C5 结论后的独立关卡。
