# 设计：C2.1b 验证集损失归因审计

> 对应 `docs/status.md` 的当前关卡。本设计是冻结 checkpoint 的诊断，不是训练实验；它只决定是否值得提出下一项单因素训练设计。

## 目标与成功判据

- **问题：**B7 的 SumNorm `KL + W1 + Huber` 与 H1 eta 辅助项，是否在共享 encoder／decoder 上出现可定位的量级失衡或任务梯度冲突，足以提出一个与 L3 不同的、可证伪的训练假设？
- **对象：**B7 `_e9ctl` 的 epoch 33 最佳 checkpoint、Q1 **验证集** 2,313 条。测试集不得用于选择 C2.1b 假设，也不得据此报告改进。
- **不重复 L3：**L3 已检验移除 KL、W1 或 Huber；它的平局不允许进行常规权重扫描。本审计只有在发现明确机制后，才允许提出一个新的单因素改变。
- **提出训练设计的必要证据：**在固定的 32 个验证 batch 梯度样本中，以下至少一项成立，并在最后 encoder FFN 与共享 decoder FFN 两个探针中复现：
  1. eDOS 与 phDOS 主谱形损失的中位梯度余弦相似度不高于 −0.10；或
  2. 某个非 KL 项的中位梯度范数至少为该任务 KL 项的 10%，且与 KL 的中位余弦相似度低于 0.95；或
  3. H1 eta 的中位梯度范数至少为两主谱形梯度范数中位数的 10%，且与其中一项的中位余弦相似度不高于 −0.10。

  上述条件只说明“可以设计”；候选设计还必须给出不等同于常规权重扫描的**有方向干预**、预计改善的
  对象、保持的因素和 pilot 成功判据。否则 C2.1b 直接 park，转入工程队列。

## 改动

- 新增只读脚本 `tools/eval/c2_1b_loss_attribution.py`：从保存的 B7 有效配置与 checkpoint 重建模型，逐条输出 SumNorm 损失分量、目标谱形统计量和归一化谱形误差；对均匀抽取的 32 个验证 batch 计算梯度范数与余弦关系。
- 不写模型权重，不调用 optimizer，不修改训练入口、默认损失或数据缓存。输出仅为版本控制的 `results/c2_1b_*` 审计文件。

## 测试关卡

- 单元测试验证 KL/W1/Huber 分解的逐条和，严格等于生产的 `sumnorm_klw_loss`；并验证梯度记录的有限性。
- 生产审计必须确认：checkpoint epoch 为 33、样本数为 2,313、split 为 valid、没有 test loader 访问、所有数值有限。

## 成本与风险

- 预计仅一次 V100 前向与 32 个 batch 的冻结反向传播；不产生检查点，不占用训练标签或训练预算。
- 验证集归因只能产生后续假设，不能证明泛化提升；如进入训练，仍须使用新的 Q1 M1×10 paired pilot，并只在结果确定后一次性评估测试集。
