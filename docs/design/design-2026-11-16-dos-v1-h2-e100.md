# 设计：dos_v1 h2 的分块吞吐与 100 轮基线

创建：2026-11-16。用户已批准。取代[35 轮执行方案](design-2026-11-16-dos-v1-baseline.md)，旧准备与失败证据保留。

本文里的 train 行数和 C 属于 2026-11-15 的标签。2026-11-18 重建后要重新准备协议，不沿用 `results/runs/dos_v1_h2_e100_throughput_20261116/pb51200/protocol.json`。模型、轮数、batch、学习率和 51200 分块仍然沿用。

## 问题与选择标准

旧数据在 35 轮学习率安排下的 best 多为 20～26 轮，不足以证明新数据更长训练无收益。
本次从头建立 seed42、100 轮的 h2 基线；100 是探索预算，不宣称已收敛或最优。
用完整 valid 选点，test 继续封存。不另训 35 轮对照，因此不能单独归因训练时长带来的收益。

先比较计算分块 51200 与 76800，保持有效 batch32、模型、数据、学习率和精度一致。
目的为运行效率选择，不使用短检后的模型预测来选型；临时更新不写 checkpoint。
预设规则：仅当 76800 的热批吞吐比 51200 高至少 5%，且峰值已分配显存不超过 21 GiB，才选择 76800；否则保留 51200。
5% 是短时资源测量的实用门槛，不是统计显著性标准。显存占用高本身不是采用理由。
任何 OOM、非有限值、契约不符停止并报告，不自动换预算重试。

## 固定训练配方

- 数据：`data/datasets/dos_v1/views/dos_v1/`，仅 train/valid，使用主分辨率 128／64 箱。
- 模型：h2，M1、ZP、staged LR2、局部2次／全局6层、共享 decoder6层、phDOS头2层、q1_coord、hidden128。
- 目标：blind E＋S、结构预测每原子总量、两任务等权；缺失标签不作零监督。
- 优化：seed42、100轮、有效 batch32、lr5e-5、FP32；前5轮从1e-5预热到5e-5，之后余弦衰减，100轮结束为1e-6。
- 不加 MACE、扰动或新正则，不改有效 batch，不追加 seed；从头初始化，不复用旧 checkpoint。
- 每轮完整 valid 各任务在其有标签的行上求均值，再各占50%；无旧数据保护参照；联合 E 最低者为 best，并列取较早轮次。
- 正常情况下完成100轮，不用35轮 checkpoint 变更预算续训。恢复只允许同一100轮协议的 latest。

验证集：7474行，eDOS6342／phDOS3080标签。train-only C：eDOS12.231741379815725／phDOS0.039093343576505346。
报告全谱两任务误差均值／中位／P90、R²中位／P10和失败率，并附来源、虚频和争议标签分组。
除 best 外分析最后20轮联合 E、分任务 E、失败率、训练与验证差距的趋势；若仍改善，明确100轮尚不能证明收敛，不自动追加训练。

## 短检与产物

工具 `tools/checks/check_dos_baseline_throughput.py`，产物根 `results/runs/dos_v1_h2_e100_throughput_20261116/`。

- train候选：原子数密度最高64个＋固定随机64个＋原子数最多32个，去重后160个。
- 用生产的6 Å周期邻居枚举，按每原子的邻居无序对数排序，构造1个高密结构＋31个普通材料、4个高密结构＋28个普通材料两个压力批次。
  这是有限候选普查，不声称找到全量最坏结构。
- 普通计时批次：从生产 sampler 的整轮中等距抽24批，同样批次先冷跑一次，再热跑两次，热吞吐取两次秒/批的中位数。
  提前组装输入，计时不包括 dataloader 等待；不包含完整缓存占用，不能当作全程资源保证。
- 另测原子数最多的32个晶体组合、两个密邻居压力批次；验证 eval模式lr=0的损失与评分一致。
- 子进程分别运行两个预算，失败立即停，不重试。每臂均只做有限临时更新，不是整轮训练。
- `pb51200/`、`pb76800/` 各含 report、protocol、preflight、effective_assembly、command与source_snapshot；决策见 `decision.json`。

v2 允许显式训练轮数和分块预算，实际值绑定训练记录、数据与 checkpoint 契约；历史 backbone_reference 仍保留35轮、默认分块，
只用于说明模型来源。v1冻结校验不变。监督脚本从 report 读取总轮数，不再写死35。

## 长时执行与验收

由独立执行 agent 接手，按选定准备目录的 `command.txt`，在 tmux 中运行 `tools/eval/dos_baseline_execute.py`。
该脚本验证指纹、独占锁、进程组、最新日志异常与10秒心跳；agent按结束／异常事件唤醒，另设约30分钟保底检查。
执行前确认无其他训练／监控。OOM、非有限值或契约不符停下报告，不改参数或重试；外部中断则核对 latest、history、优化器、随机状态及原契约后显式 `--resume`。

训练结束汇报一次，继续负责 best的valid原谱导出（`lg_valid_export.export`，指定 `spectra_out`），逐ID核对标签覆盖和原数组、
用float64独立复算E与R²、核对history选点及checkpoint，再更新日志和状态。保存分析于选定准备目录的 `analysis/`。
跨数据版本与旧分数不作因果比较，不自动采用新模型，不提交或推送Git。
