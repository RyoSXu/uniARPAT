## 已确认的接入原则

用户在本轮讨论中确认：几何只通过当前局部聚合进入新 Encoder；下列五项采用建议方案。

| 项目 | 已确认决定 | 实施含义 |
|---|---|---|
| 跨模块状态 | 沿用 `[B,L,512]` 反射偶不变标量 | B+ 的方向状态继续由局部模块内部管理，不跨局部调用传递 |
| 局部结果连接 | 保留 512 维主状态的外层残差 | 局部 `512→64→512` 输出作为残差分支，主状态有独立直连 |
| 全局模块 | 标准多头注意力，带可学习 Q/K/V 投影，配合逐原子 FFN | 不沿用旧 `q=k=v=h` 的特殊参数化；FFN 用于逐原子特征转换 |
| 残差与归一化 | 局部、注意力与 FFN 各有残差，外层采用更新前归一化 | 外层 512 维 LayerNorm 与局部内部 64 维 LayerNorm 职责分开 |
| 参数归属 | 各次更新使用独立参数 | 不同轮不绑定 Parameter；实验间复制相同初值与跨轮参数共享是不同操作 |

原子初始化继续使用既定 ZP，参数可训练；周期记录继续使用阶段性 6.0 Å、严格 `d<R`、
完整半径内镜像及自身跨胞镜像契约。本次接入不改变局部核心内部的两块、通道或公式。

新调用链的直接几何入口限定为 `晶胞/坐标 → 周期物理记录 → 局部消息`。
旧 `compute_relative_features → RPEncoding → rp_proj → rp_scores` 打分路径退出新模型，
全局混合只读取不变原子状态和 padding mask，也不接入旧 G1/G2、宏晶格等独立几何旁路。
结构仍可经原子状态影响全局注意力的 query、key 和 value。
元素身份、有效原子掩码及既定谱重建使用的原子数/价电子数保持各自职责。

## 局部与全局更新的语义

以下公式明确连接关系；dropout 沿用训练入口的显式配置，新初始化协议见下节。
令 `R` 为物理记录、`m` 为 padding mask。`Local_i` 是已有 A 或 B+ 整个局部模块，
`L_i` 是其新增的外层残差包装：

\[
L_i(h)=h+\operatorname{Local}_i(\operatorname{LN}^{L}_i(h),R,m).
\]

已有 `Local_i` 返回更新后的标量状态，原公共接口没有将其定义为增量；
在新包装中将该输出明确用作残差分支，不修改其内部 64 维残差或归一化。
每次 B+ 调用仍重新初始化内部方向状态，并在本次调用的两个块之间保留。

令 `G_i` 为注意力和逐原子 FFN 组成的全局更新：

\[
\widetilde h=h+\operatorname{MHA}_i(\operatorname{LN}^{A}_i(h),m),
\qquad
G_i(h)=\widetilde h+\operatorname{FFN}_i(\operatorname{LN}^{F}_i(\widetilde h)).
\]

每个更新结束后按同一原子槽掩码将 padding 状态置零；全 padding 和零原子边界须单独处理，
不能让全屏蔽注意力产生 NaN。无坐标更新时，物理记录可在一次模型调用中构建一次并复用。
几何相关的可学习消息仍属于局部模块，不能缓存为跨参数更新失效的激活。

一个局部模块调用含两个内部局部更新块。报告深度时分别列出局部模块调用数、
内部局部更新块数、全局注意力/FFN 更新数，不笼统写成同一个“层数”。

## 建议对照：路线与编排共同检查

**用户已确认 A/B+ 和编排需要实验选型；以下四组矩阵已提供生成与运行代码，首轮配置与暂停状态见当前状态页。**
令两种编排都含 `K` 次局部模块调用与 `K` 次全局更新，每次使用独立参数：

| 局部路线 | 分段执行：`L₁ → … → Lₖ → G₁ → … → Gₖ` | 交替执行：`L₁ → G₁ → … → Lₖ → Gₖ` |
|---|---|---|
| A | A / 分段 | A / 交替 |
| B+ | B+ / 分段 | B+ / 交替 |

`K≥2` 才形成顺序差别；`K=1` 时两列是同一编排，不应作为独立实验。
每组有 `2K` 个内部局部更新块。具体 `K` 根据完整模型成本和预算另定。

- 在同一局部路线内匹配局部/全局调用次数、模块配置与初值，比较两种顺序。
  “一次局部 + 多层全局”与“多次局部/全局交替”可以另作完整架构包比较，
  但局部计算量不同，不能把差异只归因于编排。
- 在同一编排内比较 A/B+，同时比较路线与编排的交互作用。先在一种编排下选路线，
  再只为胜出路线选择编排，可能漏掉另一种组合的收益。
- 使用现有 A/B+ 时，参数量与计算成本不同；这是实际局部候选的比较，
  不宣称参数预算相等，也不把单纯较快视为谱预测更好。
- 两路线共同的 ZP、外层归一化、全局模块和下游读出需有明确的同初值构造协议。
  相同 seed 不自动保证不同构造顺序下共享部件同初值；不能套用历史 ZP100 的整模型指纹。
- 数据版本、划分、目标、训练步数与学习率调度等对照条件在执行前写明。
  固定种子配对比较；重复种子数量由训练预算决定，单 seed 证据不宣称跨初始化稳定。

四组在一个已选定的深度上回答路线、编排与二者配合的问题；随后是否扩展深度候选，
取决于成本和结果。该顺序控制搜索规模，不保证第一次所选深度下的排序在其他深度也相同。

## 已实施的调用链与实验入口

[`LocalGlobalEncoder`](../../model/local_global_encoder.py) 注册独立的局部包装与全局块，
`execution_order` 只决定执行顺序，两个编排使用同一参数键排列。
[`Transformer`](../../model/transformer.py) 通过 `local_route/local_layout/local_depth` 启用新路径；
默认 `local_route="none"` 保持历史路径。新模型为 Z=1…118 加 padding=0 保留至少 119 行 embedding。
物理记录在一次 forward 中构建一次，所有局部调用复用；全局与 decoder 都不接收晶胞或坐标。
`prepare_shared_message_geometry` 在本次前向共享径向基、方向、计数、完整邻边对及角度基或球谐。
`Transformer.enable_local_geometry_cache` 管理独立于 state_dict 的进程内缓存；
`PeriodicGeometryCache.get` 以实际晶格与有效分数坐标内容匹配，并按当前 batch 重新映射原子槽。
改变几何、dtype、设备或半径不会沿用失效条目；坐标求导走原可导路径。
训练入口在 CUDA、无增强条件下启用，容量最多 16 GiB 且不超过设备显存的一半；LRU 与工作空间估算可继续释放条目。
该估算控制缓存占用，不保证任意训练 batch 都能放入显存；缓存分配 OOM 时释放可选缓存后走普通路径。
CPU、数据增强或几何与原子状态 dtype/设备不一致时使用普通路径，不改变输入契约。
填充状态每次更新后置零，全空结构的 decoder 使用一个零记忆 token，原始掩码继续控制 pooling 和计数。

新训练分支复用 M1 共享 decoder、两类独立谱 head、SumNorm 损失和 H1 尺度监督。
[`reconstruct_h1_spectra`](../../utils/spectral_inference.py) 生成 softmax 谱形与结构计数驱动的 blind 谱：
`eDOS = shape_e × N_val × gamma / Δe`，`phDOS = shape_p × 3N_atoms × eta / Δp`。
blind 不使用标签总量；oracle 使用标签总量诊断谱形，两种模式分别报告。空结构的物理谱为零；
这只是边界处理，不将空结构纳入训练。

[`local_global_experiment.py`](../../utils/local_global_experiment.py) 定义 `local-global-init-v1`：
同 seed 的未训练 A 构造提供共同 ZP、外层 LN、全局与下游初值，B+ 只保留自己的局部消息参数；
在同一路线的两个编排中，全部初值相同。使用标准构造器初始化，不调用历史 ZP100 单位投影/整模型指纹协议。
初值哈希与四种更新计数写入运行配置，训练开始时重新设定同 seed 随机数流。
同 seed 不承诺不同局部计算消耗完全相同的随机抽样；当前局部核心没有 dropout，编排中的全局 dropout 顺序相同。
参数复制只发生在初始化，不共享 Parameter，也不导入历史 checkpoint 续训。

[`local_global_compare.py`](../../tools/eval/local_global_compare.py) 每个 seed 生成四组隔离 tag。
默认只打印命令；显式 `--run` 才依次训练，`--summarize` 读取已有 valid 历史。
它要求显式提供 `local_depth≥2`、epochs、batch_size、lr、seeds、tag_prefix 和 selection_metric，
不借用训练脚本默认 100 轮作为已批准预算。选点指标可以是 `balanced_oracle_mae` 或
`balanced_blind_mae`，两者为两类谱 MAE 中位数的等权平均，不自动代表 eDOS 优先的采用门槛。
命令生成器默认沿用 Q1 谱坐标入口；具体共同配置可通过原训练参数显式指定。

这里的“仅允许 M1/ZP/SumNorm/H1”限定主架构、元素入口、损失归一化和尺度契约，
不表示原训练参数全部禁用。下列共同选项仍可显式选择，四组使用相同值并写入模型契约；
默认生成配方与变体必须分别注明，不据代码可用自动批准变体训练：

| 共同选项 | 命令生成器默认 | 作用与边界 |
|---|---|---|
| `q1_coord` / `q1_hidden` | 开启 / 128 | 能量与频率 bin 的查询坐标，沿用 Q1；这些坐标不是晶体空间位置 |
| `q2_fourier` | 关闭 | 将谱坐标 trunk 替换为 Fourier 形式，改变共同查询参数化 |
| `energy_code` / `edos_grid` | `none` / 无自定义网格文件 | 可显式启用 eDOS 谱轴编码；所供网格须与输出维度/单位一致 |
| `augment` / `disp_sigma` | 关闭 / 0.01 | 仅开启后对 train 分数坐标施加扰动，sigma 为分数坐标尺度；改变训练条件 |
| `use_mask` | 关闭 | 标签覆盖掩码参与损失；不改变原子 padding 或添加几何特征 |

分数扰动的笛卡尔位移为 `δx=δf A`。对于相同扰动和整晶格物理变换 `A'=AQ`，
有 `δx'=δf AQ=(δf A)Q`，分数坐标 wrap 仅改变等价周期镜像。
因此这种扰动不因笛卡尔各向异性而破坏上述物理变换规则；等价换基下的增广分布是另外的问题。
开启它仍需明确实验共同配置，结构信息仍通过局部消息入口使用。

新分支仅允许 train/valid、FP32、M1/ZP/SumNorm/H1；拒绝旧几何旁路、AMP、历史权重初始化及本轮无关辅助分支。
`model_contract` 保存完整模型参数、归一化、选点方式和训练配置；既有 `data_contract` 继续绑定晶体缓存版本。
恢复时核对两份契约并要求完整 optimizer/RNG 状态，编排不同即使参数 shape 相同也不能混用 checkpoint。
`--summarize` 核对保存配置与选点列，未跑组标为 pending、未达预算组标为 partial。
history 存在而配置缺失时，明确报告组 tag、配置/历史路径和恢复原配置的要求；
这种产物无法核验身份，不降级为 pending，也不凭 history 认定完整实验。
历史 ZP100 入口与 checkpoint schema 保持原有语义。

`--run` 遇任一组异常立即停止，不自动继续或重试。定位失败 tag 并排除原因后，
使用相同完整参数、seed 列表和 tag_prefix 重跑队列：已完成组读取完整 checkpoint 后不追加 epoch，
未完成组从最近保存的完整 epoch 恢复，尚未启动组从初始化开始。
如果修复需要改变 batch、深度、预算或其他契约字段，应使用新的 tag_prefix 建立新的对照；
旧 checkpoint 不通过删除或改写规避契约校验。

## 验收、成本与后续决定

**先完成无参数更新的完整模型接入验收，再确定具体训练预算。**

- 架构论证：相对几何、局部 O(3) 运算与标量输出、外层残差/LN、全局混合、pooling、
  两类 decoder/head、eta/gamma 或尺度及最终谱重建都在 E(3) 论证范围。
- 数值证据：固定权重与 eval，测试平移、旋转和反射后的两类谱及尺度输出；
  有限变换测试与架构论证分别报告。原子重排、等价晶胞和超胞一致性按各自契约另报。
- 连接验证：掩码、空结构、参数注册以及谱输出反向到全局、局部和 ZP 的有限梯度；
  不通过 detach 切断模块接口。
- 完整成本：测几何构建、完整前向/反向时间与峰值内存，再决定可用 batch、深度和训练量。
  现有局部 GPU 短测不自动代表正式模型吞吐；AMP 尚需独立验收。
- 训练判断：使用 train/valid，分别报告 eDOS/phDOS、blind/oracle 指标；
  优先检验 eDOS 结构条件谱形，同时按预先确定标准保护 phDOS，并联合报告耗时与内存。

ZP100/B7 继续作为既定参考；它们的旧报告使用原 Q1，不能自动代表当前修复版输入下的结果。
严格对照需注明数据与输入口径，具体参考复评或训练对照另定。
新模型不能当作历史 checkpoint 的续训；历史复核路径和已有产物继续保留。

接入与无更新验证结果见实施日志。首轮已使用 K=2、35 epochs、batch=32、lr=5e-5、seed=42 和
`balanced_oracle_mae`；A/staged 完成 21 轮后队列由用户暂停，关闭重计算、大分块与几何缓存尚未用于后续正式训练。
最终路线/编排/深度、采用门槛和结果对应行动尚未选定；本次工程修改不自动批准恢复或扩展预算。
